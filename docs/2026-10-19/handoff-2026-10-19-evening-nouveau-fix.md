# Handoff: зависания GTX 560 Ti на Ubuntu 26.04 — причина найдена

Дата: 2026-10-19, вечер (19:58–22:55 МСК). Продолжение `handoff-2026-10-19-ubuntu-gtx560ti-freeze.md`.

## 1. Итог в одной фразе

Зависания вызывала гонка в драйвере nouveau: при удалении графического объекта по запросу программы
(«новый» путь `nouveau_abi16_ioctl_del`) драйвер не дожидался, пока канал программы закончит работу.
Программы на Chromium (Яндекс, Claude, Cursor) при старте создают и сразу удаляют пробные 3D-объекты;
если карта в этот момент занята рабочим столом (анимация запуска из Dash, движение мыши), она обращается
к уже обнулённому контексту → `PAGE_NOT_PRESENT at 0` (HUB/CTXCTL) → канал убит → драйвер не восстанавливается.
Исправление (15 строк) добавляет ожидание `nouveau_channel_idle()` перед удалением — как в старом пути `GPUOBJ_FREE`.

Проверка: 9 запусков Claude + 1 Яндекса из Dash подряд — 0 ошибок (до исправления падало почти каждый раз).

## 2. Текущее состояние машины

- Установлен **наш модуль**: `/lib/modules/7.0.0-38-generic/updates/nouveau-engobj-idle/nouveau.ko`
  (исходники Linux 7.0.14 + патч `nouveau-abi16-idle-before-engobj-del.patch`, в `~/nouveau-build/nouveau-engobj-idle/`).
  При срабатывании пишет в журнал `nouveau-engobj-idle: idling chid N before deleting oclass XXXX`.
- Параметры загрузки: `quiet splash nouveau.hdmimhz=297` + **временно** `nouveau.debug=fifo=trace,gr=trace`
  (очень подробный журнал, ~9 тыс. строк/мин — выключить, см. ниже). Копия до трассировки: `/etc/default/grub.before-trace`.
- `nouveau.hdmimhz=297` — правильная настройка: монитор MSI MPG 271QX OLED, родной режим 2560×1440@59.95 = 241,5 МГц.
- Частоты карты: стоят на минимуме (ядро 50 МГц / память 135 МГц), nouveau на Fermi их не переключает.
- Ядро при падении сохраняет отчёты в `/var/crash` (kdump включён).

## 3. Команды

Выключить подробный журнал (исправление остаётся):
```bash
sudo cp /etc/default/grub.before-trace /etc/default/grub && sudo update-grub
```
Откатить исправление (вернуть стандартный nouveau Ubuntu):
```bash
sudo rm /lib/modules/$(uname -r)/updates/nouveau-engobj-idle/nouveau.ko && sudo depmod -a && sudo update-initramfs -u && modinfo -n nouveau
```
Аварийная перезагрузка при зависании: Alt + PrtSc, по очереди S, U, B (журнал сохраняется).

## 4. Что выяснено и закрыто

| Гипотеза | Вердикт |
|---|---|
| Разгон HDMI (`hdmimhz=297`) | не причина: падало и до него, и без него |
| Диск / порт `ata2` | не причина: это пустой eSATA с Hot Plug, моргает всегда |
| Нагрузка 3D как таковая | не причина: glmark2 (GL и GLES) проходит чисто |
| Медленная карта / таймауты | не первопричина: драйвер ждёт 10 с × 13 раз; но низкая частота расширяет «окно» гонки |
| Поднять частоты (снять `allow_reclock=false`) | не работает: режим 07 — память не переключается, 0f — timeout `gf100_clk_prog_3`, карта встаёт |
| Запуск программ рабочим столом vs из Терминала | **подтверждено**: из Терминала 11/11 без ошибок, из Dash — падения |

## 5. Открытые задачи (по порядку)

1. **Обновление ядра сотрёт исправление** (модуль привязан к 7.0.0-38). Варианты: автопересборка (DKMS) и/или
   отправить патч разработчикам nouveau (в Linux 7.3 правки нет) — единственный путь, чтобы исправление пришло с обновлениями.
2. **Неделя обычной работы** с исправлением и выключенным подробным журналом — проверка критерия «готово».
3. **Падение ядра при «шторме»** быстрых запусков/закрытий: `nouveau_fence_sync` обращается к каналу уже закрытой программы
   (use-after-free). Патч из рассылки (E. Fleury, LKML 2026-07-23, проверка `prev->cli`) **недостаточен** — проверено:
   падает дальше с мусорным указателем. Два отчёта: `/var/crash/202610192157`, `/var/crash/202610192222`. В обычной работе за 3 дня не встречалось.
4. **Частоты**: разбирать перенастройку генератора частоты (`gf100_clk_prog_3`) для GF114 — отдельный проект.
5. Мелочь: выключить Hot Plug на eSATA в BIOS, если мешает шум в журнале.

## 6. Как работать дальше (технически)

- Терминала на машине у ассистента в этой схеме нет; журнал читается напрямую из `/var/log/journal` (доступ выдан),
  команды запускает Александр. Сборка модуля: исходники готовятся ассистентом, `make -C /lib/modules/$(uname -r)/build M=$PWD/nouveau`.
- Исходники Linux 7.0.14 (ядро Ubuntu 7.0.0-38.38 основано на 7.0.14) брались с GitHub-зеркала gregkh/linux.
