# Генератор частот ядра: что в пакете для тестировщиков, белые пятна и путь в апстрим (31.10.2026)

Пакет для rox4d (GF106) и Q0AL (GF114): сборка 6F1D5930 (lab/0002 — генератор, правило M, проверка read_pll, обход
бэкпорта в clk/base.c), режим «только ядро» (`lab_mem=0`, `lab_vbios_src=1`). Память не трогается.

## 1. Что в пакете вычисляется из VBIOS платы, а что — правило или таблица из записей

| что | откуда | проверено |
|---|---|---|
| частоты узлов на уровнях | таблица уровней VBIOS | всегда так |
| PLL или делитель у GPC, ROP, hubk07, hubk06, hubk01 | флаг узла (биты 14–15), П12 | 425 из 425 узлов в базе; наша карта 15/15 (тест 66) |
| основной делитель GPC — на частоту высшего уровня на делителях | П13 | база, кроме GF119 в 304+ (открыто) |
| коэффициенты PLL; у GPC — наибольшее M | расчёт по пределам из таблицы PLL VBIOS, П14 | 30 из 30 с эпохой драйвера; на железе — впервые у Q0AL |
| напряжение | формула карты напряжений VBIOS (скорость кристалла из предохранителя) + округление вверх до ступени VID (так делает и nouveau) | П15: 57 из 57 (Fermi, VID); rox4d 1,1056 → 1,1125, Q0AL 1,0125 |
| опора PLL 405 через делитель опоры, PLL без бита 0x10, PMU 202,5 | общие правила Fermi (ошибки nouveau 1–3) | все записи |
| скобка замедления, «команда» делителя, защита переключателя | общие правила последовательности | наша карта; rox4d — подъём на 0f прошёл |
| **код замедления в скобке** (/6, /2) | **таблица по чипу в коде**: GF106 → /2, иначе /6 | верно для GF106 и GF114; для GF100 (/8), GF104/GF108/GF119 (/2), GF110 (/6 или /2) — нет |
| **ожидание в скобке** | **наше решение**: по аппаратному признаку (~2,3 мкс) + запас ключом (rox4d 16 мкс ≈ NVIDIA на его карте; Q0AL 0) | у NVIDIA — фиксированное время по группе 0x020130; источник не установлен |

Итог: **значения** частот и напряжения в пакете целиком из VBIOS, без данных нашей карты. **Как переключать** — общие
правила из записей NVIDIA; два параметра скобки (код и время) — таблица и наше решение, а не вычисление.

## 2. Белые пятна (не знаем)
1. **Откуда время ожидания в скобке** (8 / 4,5 / ~18 / ~150 мкс). Совпадает с группами 0x020130 (пишет init-скрипт VBIOS),
   формулы нет. → Е17 на стенде: подменить 0x020130 перед загрузкой NVIDIA 390 и посмотреть, сдвинется ли время.
2. **Откуда код замедления** (/2, /6, /8). У GF110 1080 и 1086 разный при одинаковых полях VBIOS 0x020160/164; у GF108 менялся
   с версией драйвера. → сравнить трассы одного чипа разных версий; тот же приём, что Е17, с 0x020160.
3. **Делитель GPC у GF119 в драйверах 304+** (A = 00 + пост-делитель /3 на спуске) — правило П13 там не выполняется.
4. **Напряжение ШИМ у ноутбучных Fermi** (не VID) — не разобрано.
5. **Делитель PMU на других чипах** — у наших двух стоит с POST, у прочих не проверяли.
6. **GF117 / GF119 без скобки** у части плат — путь не изучен.

## 3. Серые зоны (знаем, что NVIDIA делает иначе; у нас работает, но не так)
1. **Ожидание по признаку вместо фиксированного времени.** В плохих сессиях (нужное время успокоения 2,3–3,1 мкс) признак
   стоит на границе; спуск спасает «команда» (`lab_nv_div_late`), подъём изредка застревает (66б: 2 на 2000, ядро на один заход
   остаётся на 810). Ожидание как у NVIDIA (8 / 4,5) — 0 на 3000 (65а), но вместе с «командой» и без ключей $NV не проверялось.
2. **Порядок переключателей**: NVIDIA — хабы первыми вверх (7 8 0 1 2), последними вниз; у нас 0 1 2 7 8 (`lab_order=0`,
   тест 12: не причина зависаний GR).
3. **PLL hubk06**: NVIDIA её не трогает (ставит init-скрипт), мы на каждом подъёме выключаем и захватываем заново с тем же
   коэффициентом (на трёх платах — тот же, что у NVIDIA).
4. **Переход ядра через 405 перед PLL** (`lab_gpc_pre405`), пост-делитель хабов до переключателя (`lab_nv_hubpost`), hubk07
   рядом с памятью, PCIe в конце спуска — у NVIDIA есть, в пакете нет (тесты 25–28: не обязательно; возможная связь с двумя
   застреваниями 66б не проверена).
5. **PXBAR 2/3 вокруг смены, 0x00e9e0, 0x001548, 0x610300, выдержка ~195 мкс после смены VID** — у NVIDIA есть, у нас нет.
6. **Защита переключателя** повторяет только уход с PLL; при застревании на подъёме — без повтора (ядро остаётся на делителе).
7. **Причина плохих сессий** — по данным свойство чипа (время успокоения), ядро Linux больше не выделяется (31.10: 1 плохая из 6
   на ядре 42).

## 4. Что сделать, чтобы закрыть
| шаг | закрывает | где |
|---|---|---|
| результаты rox4d и Q0AL в режиме «только ядро» | генератор на двух чужих платах; правило M на железе (Q0AL); hubk06 на PLL по флагу (Q0AL) | у них |
| Е17 (0x020130 → время ожидания) | пятно 1; даёт правило вместо таблицы | стенд 2011, NVIDIA 390 |
| ожидание по таблице группы 0x020130 в драйвере (вместо признака и ключа запаса) + ночной тест в плохой сессии вместе с «командой» | серая 1; ключ `lab_therm_wait_us` больше не нужен | наша карта |
| порядок как у NVIDIA (`lab_order=1`) и «не трогать PLL hubk06, если уже захвачена с тем же коэффициентом» — по одному, ночью | серые 2, 3 | наша карта |
| `lab_gpc_pre405=1` в пакете — тест «только ядро» в плохой сессии | серая 4 (два застревания на подъёме) | наша карта |
| повтор и на подъёме в защите переключателя | серая 6 | код + тест |
| таблица кодов замедления для всех Fermi из базы трасс | пятно 2 (как таблица) | база |

## 5. Путь в апстрим (ядро Fermi, без памяти)
Серия патчей без ключей `lab_*`, каждый — отдельное исправление с обоснованием:
1. выбор PLL / делителя по флагу узла из таблицы уровней VBIOS (вместо арифметики);
2. PLL без бита 0x10 после захвата; опора PLL hubk06 через делитель опоры (405, а не 1620); проверка M, P на ноль в read_pll;
3. основной делитель GPC на частоте высшего уровня на делителях; PMU — без пересчёта (202,5);
4. наибольшее M у PLL GPC (как NVIDIA 304+), если сопровождающие сочтут это нужным — частота та же;
5. скобка замедления PTHERM вокруг переключателей и пост-делителей с ожиданием по чипу/группе (черновик RFC —
   docs/upstream/rfc-gf114-clk-slowdown-draft.patch) и смена делителя прямо перед переключателем;
6. тайм-аут переключателя — не продолжать переход (не снижать напряжение, если узел остался на PLL).
Перед отправкой: результаты двух тестировщиков, ожидание по таблице вместо признака, проверка на нашей карте в плохой сессии.
