# Смена частоты памяти по смыслу: словарь шагов и сквозной скелет (23.11.2026)

Слой смыслов перед генератором. Источники: открытый драйвер NVIDIA для Tegra K1 `drivers/memory/tegra/tegra124-emc.c`
(DDR3L, порядок с комментариями); nouveau `ramgk104.c` (ветки DDR3 `gk104_ram_calc_sddr3` и GDDR5), `ramgf100.c`, `sddr3.c`;
наш перевод операций NVIDIA (lab ramgf100.c, октябрь). Разметка — `lab/db-mem-steps.py` по кластерам
(mem-steps-0.6.md; кластеры — mem-survey.md §10). «?» — смысл не установлен.

## 1. Как меняет частоту DDR3 драйвер NVIDIA для Tegra (tegra124-emc.c, prepare/complete_timing_change)
1. Решить, меняется ли DLL: по биту 0 MR1 (DLL выключена на низких частотах).
2. Выключить энергосбережение (динамическое самообновление); подготовить площадки DQ/DQS (смещение, VREF); выдержка 5–30 мкс.
3. Терминация; выключить автокалибровку.
4. Записать новые тайминги в «теневые» регистры (вступают в силу в момент смены такта).
5. Настройка арбитража контроллера памяти под новую частоту.
6. DDR3, если DLL включается — длинное ожидание после MRS (512 тактов).
7. DDR3, если DLL выключается — записать MR1 с выключенной DLL ДО самообновления.
8. Выключить контроллер обновления; DDR3 — войти в самообновление.
9. **Смена такта.**
10. DDR3 — выйти из самообновления; включить обновление.
11. Регистры режима: MR1, MR2, MR0 (у MR0 — сброс DLL, если DLL включилась).
12. Калибровка ZQ (длинная), если включается.
13. Вернуть автокалибровку и энергосбережение.

## 3. Сквозной скелет (все кластеры, кроме различий)
**Рамка — общая от GT21x до Pascal:** ждать кадр → пауза дисплея → оп 0x34 → стоп доступа … пуск доступа → оп 0x34 →
дисплей снова → конец. Рамка не про память, а про то, чтобы никто не читал VRAM во время смены.

**Ядро (Fermi → Pascal, DDR3 и GDDR5):**
КОНТРОЛЛЕР → PRECHARGE / авто-обновление выкл / REFRESH (у Kepler+ — бит 31 0x10f200 между двумя REFRESH) → ИНТЕРФЕЙС
0x10f090 → **смена такта (PLL, источник)** → ЛИНИИ, ТАЙМИНГИ → ИНТЕРФЕЙС 0x10f090 обратно → PRECHARGE → REFRESH →
авто-обновление вкл → **MR** (у DDR3 Kepler: MR2, MR1, MR0 с DLL) → КОНТРОЛЛЕР.

**С Tegra совпадает по смыслу и по порядку:** обновление выключить → такт → обновление включить → MR1/MR2/MR0 с DLL.
Отличие: у Tegra явное самообновление на время смены такта; у GPU на этом месте — бит 31 0x10f200 (гипотеза).

## 4. DDR3 → GDDR5: продолжение
- DDR3 (К3, К4): ядро без обучения; MR — MR0/MR1/MR2.
- GDDR5 (К1, К2, К5, К8): то же ядро **плюс** ОБУЧЕНИЕ линий (в начале и в конце), больше MR (MR2…MR8), ПИТАНИЕ/VREF,
  у полных переходов — тайминги расширены. Гипотеза «GDDR5 = DDR3 + обучение/WCK» подтверждается разметкой.
- Длина полного скрипта: DDR3 56–62 записей во всех поколениях; GDDR5 72 (Fermi) → 84 (Kepler) → 91 (Pascal) → 103 (GDDR5X).
  Усложняется именно добавочная часть GDDR5.

## 5. Fermi — переходный и «перестраховочный»
Fermi добавляет к ядру то, чего нет ни до (GT21x), ни после (Kepler): пару «0x13d8x4 + оп 0x3a» вокруг КАЖДОЙ смены в домене
тактов (до 7 раз за скрипт), оп 0x39, у GDDR5 — пачку 0x0b/0x02/0x0d/0x22/0x04, и отдельную «предварительную» часть до
остановки доступа (такт, 0x10f808, PFB). Это совпадает с картиной ядра: на Fermi NVIDIA ставит скобки и выдержки там, где
Kepler обходится без них. Рабочая гипотеза: 0x3a — ожидание/синхронизация, нужная только Fermi. Проверено (751 скрипт):
- в 0x13d8x4 пишется **всегда 0** (1087 записей из 1087), сразу за ней — оп 0x3a;
- аргумент 0x3a — число 1…10 (чаще 1 и 2); **не счётчик шагов**: в 84 скриптах из 107 идёт не по порядку (например 4, 1, 10, 2);
- оп 0x34 стоит **вплотную к стоп/пуску доступа (0x20) в 1692 случаях из 1726 (98 %)** у всех поколений с GT21x; аргумент —
  10/11/12/13 (парами), похоже на номер события вокруг остановки доступа; в рамку входит уверенно, смысл — ?;
- оп 0x39: аргументы 78, 186 (чаще всего), 12–14.

Смысл 0x3a и 0x13d8x4 открыт. То, что их нет у Kepler+ при том же ядре протокола, — довод, что для самой памяти они не
обязательны (мы их пропускаем, и на GF114/GF106 повтор без них чистый).

## 6. Что это даёт генератору
Генератор строится по шагам словаря, а не по скопированному скелету: рамка (общая), ядро (общее), добавки GDDR5 (обучение,
MR2…8), особенности Fermi (0x3a/0x13d8x4 — по чипу, адрес из таблицы чипа). Непонятые «?» в генераторе явно помечены.
