# Смена частоты памяти по смыслу: словарь шагов и сквозной скелет (23.11.2026)

Слой смыслов перед генератором. Источники: открытый драйвер NVIDIA для Tegra K1 `drivers/memory/tegra/tegra124-emc.c`
(DDR3L, порядок с комментариями); nouveau `ramgk104.c` (ветки DDR3 `gk104_ram_calc_sddr3` и GDDR5), `ramgf100.c`, `sddr3.c`;
наш перевод операций NVIDIA (lab ramgf100.c, октябрь). Разметка — `lab/db-mem-steps.py` по кластерам
(mem-steps-0.6.md; кластеры — mem-survey.md §10). «?» — смысл не установлен.

## 1. Как меняет частоту DDR3 драйвер NVIDIA для Tegra (tegra124-emc.c, prepare/complete_timing_change)
1. Решить, меняется ли DLL: по биту 0 MR1 (DLL выключена на низких частотах).
2. Выключить энергосбережение (динамическое самообновление); подготовить площадки DQ/DQS (смещение, VREF); выдержка 5–30 мкс.
3. Терминация; выключить автокалибровку.
4. Записать новые тайминги в «теневые» регистры (вступают в силу в момент смены такта).
5. Настройка арбитража контроллера памяти под новую частоту.
6. DDR3, если DLL включается — длинное ожидание после MRS (512 тактов).
7. DDR3, если DLL выключается — записать MR1 с выключенной DLL ДО самообновления.
8. Выключить контроллер обновления; DDR3 — войти в самообновление.
9. **Смена такта.**
10. DDR3 — выйти из самообновления; включить обновление.
11. Регистры режима: MR1, MR2, MR0 (у MR0 — сброс DLL, если DLL включилась).
12. Калибровка ZQ (длинная), если включается.
13. Вернуть автокалибровку и энергосбережение.

## 3. Сквозной скелет (все кластеры, кроме различий)
**Рамка — общая от GT21x до Pascal:** ждать кадр → пауза дисплея → оп 0x34 → стоп доступа … пуск доступа → оп 0x34 →
дисплей снова → конец. Рамка не про память, а про то, чтобы никто не читал VRAM во время смены.

**Ядро (Fermi → Pascal, DDR3 и GDDR5):**
КОНТРОЛЛЕР → PRECHARGE / авто-обновление выкл / REFRESH (у Kepler+ — бит 31 0x10f200 между двумя REFRESH) → ИНТЕРФЕЙС
0x10f090 → **смена такта (PLL, источник)** → ЛИНИИ, ТАЙМИНГИ → ИНТЕРФЕЙС 0x10f090 обратно → PRECHARGE → REFRESH →
авто-обновление вкл → **MR** (у DDR3 Kepler: MR2, MR1, MR0 с DLL) → КОНТРОЛЛЕР.

**С Tegra совпадает по смыслу и по порядку:** обновление выключить → такт → обновление включить → MR1/MR2/MR0 с DLL.
Отличие: у Tegra явное самообновление на время смены такта; у GPU на этом месте — бит 31 0x10f200 (гипотеза).

## 4. DDR3 → GDDR5: продолжение
- DDR3 (К3, К4): ядро без обучения; MR — MR0/MR1/MR2.
- GDDR5 (К1, К2, К5, К8): то же ядро **плюс** ОБУЧЕНИЕ линий (в начале и в конце), больше MR (MR2…MR8), ПИТАНИЕ/VREF,
  у полных переходов — тайминги расширены. Гипотеза «GDDR5 = DDR3 + обучение/WCK» подтверждается разметкой.
- Длина полного скрипта: DDR3 56–62 записей во всех поколениях; GDDR5 72 (Fermi) → 84 (Kepler) → 91 (Pascal) → 103 (GDDR5X).
  Усложняется именно добавочная часть GDDR5.

## 5. Fermi — переходный и «перестраховочный»
Fermi добавляет к ядру то, чего нет ни до (GT21x), ни после (Kepler): пару «0x13d8x4 + оп 0x3a» вокруг КАЖДОЙ смены в домене
тактов (до 7 раз за скрипт), оп 0x39, у GDDR5 — пачку 0x0b/0x02/0x0d/0x22/0x04, и отдельную «предварительную» часть до
остановки доступа (такт, 0x10f808, PFB). Это совпадает с картиной ядра: на Fermi NVIDIA ставит скобки и выдержки там, где
Kepler обходится без них. Рабочая гипотеза: 0x3a — ожидание/синхронизация, нужная только Fermi. Проверено (751 скрипт):
- в 0x13d8x4 пишется **всегда 0** (1087 записей из 1087), сразу за ней — оп 0x3a;
- аргумент 0x3a — число 1…10 (чаще 1 и 2); **не счётчик шагов**: в 84 скриптах из 107 идёт не по порядку (например 4, 1, 10, 2);
- оп 0x34 стоит **вплотную к стоп/пуску доступа (0x20) в 1692 случаях из 1726 (98 %)** у всех поколений с GT21x; аргумент —
  10/11/12/13 (парами), похоже на номер события вокруг остановки доступа; в рамку входит уверенно, смысл — ?;
- оп 0x39: аргументы 78, 186 (чаще всего), 12–14.

Смысл 0x3a и 0x13d8x4 открыт. То, что их нет у Kepler+ при том же ядре протокола, — довод, что для самой памяти они не
обязательны (мы их пропускаем, и на GF114/GF106 повтор без них чистый).

## 6. Что это даёт генератору
Генератор строится по шагам словаря, а не по скопированному скелету: рамка (общая), ядро (общее), добавки GDDR5 (обучение,
MR2…8), особенности Fermi (0x3a/0x13d8x4 — по чипу, адрес из таблицы чипа). Непонятые «?» в генераторе явно помечены.

## 7. Адрес 0x13d8x4 — от числа разделов памяти (проверено на базе)
Генератор на чужих платах расходился с NVIDIA прежде всего здесь — только адресом, значение всегда 0. Адрес не по чипу: у
разных плат GF114 он разный. Сопоставление с номерами разделов, в которые пишут те же скрипты (0x110000 + 0x1000·i):

| чип | активные разделы в скриптах | адрес |
|---|---|---|
| GF108 (DDR3 и GDDR5) | 0, 1 (два контроллера, **один** раздел ROP/L2) | 0x13d834 |
| GF106 (GTS 450) | 1, 2 (раздел 0 выключен) | 0x13d874 |
| GF114 (3 раздела), GF116 | 0, 2, 3 / 0, 1, 2 | 0x13d8b4 |
| GF114 (наша, 4), GF104 | 0…3 | 0x13d8f4 |
| GF110 / GF100 (5 разделов) | 1…5 | 0x13d934 |
| GF110 / GF100 (6) | 0…5 | 0x13d974 |

**Правило: адрес = 0x13d834 + 0x40 · (n − 1), n — число АКТИВНЫХ разделов** (выключенные не считаются: GF106 с выключенным
разделом 0 — n = 2). Единственная тонкость — GF108: два контроллера памяти, но, по правилу, n = 1 — это сходится с гипотезой
из chip-clusters.md «один раздел, разделённый надвое» (и с тем, что именно у GF108/GF117 NVIDIA ставит XBAR снаружи памяти).
У GF117 и GF119 пары 0x13d8x4 + 0x3a нет вовсе. Похоже на запись в регистр ПОСЛЕДНЕГО активного раздела массива с шагом 0x40
(смысл самой записи и оп 0x3a — ?). Для генератора это закрывает самую частую строку расхождений: адрес из числа разделов,
которое драйвер читает из железа.

## 8. Общая нить: топология памяти (разделы × контроллеры) — скрытая ось
Это уже четвёртое различие Fermi, которое ложится не на чип и не на тип памяти, а на то, как устроена память внутри кристалла
(число активных разделов, контроллеров, подразделов; драйвер NVIDIA читает их при старте из 0x022438/0x02243c и маски
выключенных; в VBIOS этого нет):

| наблюдение | где | что решает |
|---|---|---|
| порядок «шина XBAR снаружи памяти» | GF108, GF117 (опыт 119, разбор сбоя sasim44) | один раздел из двух подразделов |
| провод «хаб ← PLL XBAR2CLK» | только GF108 (опыт 103) | та же раскладка |
| записи сценария unk1c по разделам (0x11x640/644) | у GF106/GF116 нет 0x113644 (октябрь) | число разделов |
| **адрес 0x13d8x4 = последний активный раздел** | все Fermi с ≥ 2 контроллерами (§7) | число активных разделов; **GF108 считается за ОДИН** |
| пара 0x13d8x4 + оп 0x3a есть / нет | есть там, где контроллеров ≥ 2 (GF108: 1 раздел, 2 контроллера); **нет у GF117 и GF119** (1 и 1) | число контроллеров |

Что это меняет:
1. **Первое прямое подтверждение из поведения NVIDIA**, что драйвер считает GF108 одним разделом (раньше было только по
   envytools, «напрямую не проверить» — chip-clusters.md). Значит, версия «XBAR снаружи там, где поток сходится в один
   раздел из двух подразделов» получила вторую, независимую опору.
2. **Гипотеза про оп 0x3a (синхронизация контроллеров) — проверена частично и ослаблена.** За: нет у GF117/GF119 (один
   контроллер), нет у Kepler+. Против: у GF106 и GF116 запись в 0x13d8x4 есть, а **оп 0x3a в их трассах нет**; аргумент 0x3a
   не ограничен числом разделов (GF108 — один раздел, аргументы 1…4; GF104/GF114 — до 10). Значит, сама запись в регистр
   последнего раздела — правило топологии (твёрдо), а 0x3a — отдельная операция, смысл — ?.
3. **Для правил драйвера:** вместо списков чипов (lab_nv_xbarmem по чипу, адрес 0x13d8x4 по чипу) — одно правило от
   топологии, прочитанной из железа. Это и есть «одно правило вместо таблиц NVIDIA по чипу».

## 9. Топология из железа: правило проверено на регистрах, и она сквозная (lab/db-mem-topo.py, mem-topology-raw.md)
Из трасс сняты первые чтения тех же регистров, что читает nouveau: 0x022438 (разделов FBP), 0x02243c (контроллеров FBPA),
0x022554 (маска выключенных), 0x17e8dc[31:28] (подразделов L2 на раздел).

**Fermi (44 трассы):** адрес 0x13d834 + 0x40·(активных − 1) совпал со скриптами NVIDIA на всех трассах, где он есть.
Подразделов: 2 у всех, кроме **GF119 — 1**. Отсюда правило порядка XBAR без списка чипов:

**шина XBAR снаружи памяти ⇔ активный раздел один И подразделов в нём ≥ 2** → GF108 (1 × 2) и GF117 (1 × 2) — да;
GF119 (1 × 1) и все 2–6-раздельные — нет. Совпадает с порядком NVIDIA на всех 9 чипах Fermi.
(Контроллеры FBPA драйвер NVIDIA читает только у однораздельных чипов: GF108 — 2, GF117/GF119 — 1.)

**Сквозь поколения — те же регистры, тот же смысл:**
- Kepler: подразделов на раздел стало **4** (у Fermi 2) — смена архитектуры L2 видна прямо в регистре;
- **GK208 (nv108) — 1 раздел × 2 подраздела: та же топология, что у GF108/GF117**, в поколении Kepler;
- Maxwell/Pascal: 0x022438/0x02243c читаются (GM108, GP108 — по 1 разделу), маска и подразделы — в другом месте (не читались).
Проверка правила на Kepler: у GK208 смотреть порядок XBAR и скрипта памяти в записях хоста (в самих скриптах Kepler такта
XBAR нет). Если правило топологическое, у GK208 NVIDIA тоже должна держать XBAR снаружи памяти.

**Важно, чтобы не путать (23.11, после обсуждения).** Порядок по умолчанию НЕ менялся и не зависит от топологии: шина XBAR
снаружи памяти на ВСЕХ чипах (lab_nv_xbarmem = 1) — наше сознательное отступление от NVIDIA на классических Fermi (проверено:
тесты 28, 69, прогон rox4d, опыт 119). Топология объясняет, ПОЧЕМУ NVIDIA различает чипы, и даёт генератору адрес 0x13d8x4;
положение −1 — только для сравнительных опытов. Объяснение для читателя: docs/deviations.md, «The crossbar/memory order».

**Драйвер (лаб. сборка 1123a):** lab_nv_xbarmem = −1 («как NVIDIA») теперь решает по топологии из железа, а не по списку
чипов; при первом переходе в журнал пишется строка «LAB топология памяти: разделов …, подразделов … → шина XBAR снаружи/
внутри; адрес синхронизации …». По умолчанию порядок по-прежнему 1 (шина снаружи на всех чипах — предохранитель).
**Генератор:** адрес 0x13d8x4 по топологии → сходство скелета с NVIDIA выросло: GF108 81 → 91 %, GF106 68 → 76 %, GF110 79 →
86 %, GF116 82 → 91 %, GF114 92 → 94 %.

## 10. Fermi — не одно поколение
Сводя ось А (топология памяти) и ось Б (периферия: дисплей, уровни, PMU — chip-clusters.md) и кластеры скриптов памяти:
1. **«Классический Fermi»** GF100/104/106/110/114/116 — 2–6 разделов × 2 подраздела, свой язык скриптов (0x3a, 0x13d8x4,
   скобки, выдержки);
2. **линия GF108** — один раздел из двух подразделов: другой порядок XBAR, провод хаба от XBAR, «один раздел» в адресах;
3. **подсемейство GF119/GF117** — периферия и уровни как у Kepler; память GF117 по скриптам — Kepler DDR3, без 0x3a.
Драйвер «для Fermi» по факту — два-три драйвера стабильных поколений; правила, выведенные из топологии и VBIOS, позволяют
держать их в одном коде без списков чипов.
