# Отложенные вопросы (вернуться позже)

Список того, что найдено, но не разобрано до конца: откуда вопрос, что известно, как проверить. Новые — сверху.

## Ядро

### Узел 09 («copy» у nouveau) — имя NVIDIA и что он тактирует (23.11)
- **Откуда:** разбор узлов при ответе тестировщику (NVS 315, 23.11); атлас узлов docs/2026-10-31/node-atlas.md.
- **Известно:** источник 0x137184; частота в VBIOS есть (NVS 315: 405 МГц на 07, 540 на 0f), драйвер её ставит, работает.
  В коде nvgpu (Kepler/Maxwell Tegra) такого узла нет, в таблице доменов Kepler — тоже. Из 13 имён доменов Fermi свободны
  HOSTCLK, LEGCLK, XCLK, PCIEGENCLK.
- **Как проверить:** на нашей GF114 понизить узел (только он) и смотреть, что замедлится — копирование памяти (copy engine),
  обмен по PCIe, загрузка команд. Счётчик узла — для подтверждения частоты. Безопасность: опыт 104 (смена источника SYS2CLK
  без скобки вешала машину) — только с тепловой скобкой и по одному шагу.

### GF119: LTC2CLK (узел 01) на кварце — откуда тактируется кэш L2 (23.11)
- **Откуда:** отчёт NVS 315 (узел получил 1080 при VBIOS 1099); проверка по базе — docs/deviations.md (NVIDIA на всех
  4 платах GF119 оставляет узел на кварце 27 МГц на всех уровнях; после POST он тоже на кварце).
- **Известно:** у GF119 один раздел памяти из одного подраздела (0x17e8dc); кэш работает, значит, такт у него откуда-то есть.
- **Мысль пользователя (23.11):** раз мы на своей карте умеем свободно менять источники узлов, найти источник — не проблема.
  **Уточнение:** на GF114 этот узел используется (кэш на нём), поэтому опыт нужен на самом GF119 — у тестировщика (NVS 315).
  Метод: нагрузка, упирающаяся в кэш L2, и по очереди понижать узлы-кандидаты (XBAR2CLK, SYS2CLK) — тот, при котором падает
  скорость кэша, и тактирует его; счётчики узлов подтверждают частоты. Без нашей карты — только с тестировщиком, по шагу.
- **Кандидат-правило:** узел, который VBIOS оставил на кварце, на этой плате не используется — не трогать (одно правило без
  списка чипов). Ввести после подтверждения на GF119.

### Предупреждение сборки: кадр стека 1216 байт в clk/gf100.c
- Отладочная функция; на работу не влияет. Почистить при следующей уборке (заметил тестировщик 23.11).
