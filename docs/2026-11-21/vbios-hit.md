# Попадание в частоты VBIOS: одно правило, один допуск (21.11.2026)

**Повод.** Замер sasim44 (ASUS GT 630, GF108) 21.11: на 0f HUB2CLK = 1282,5 МГц (PLL SYS2CLK), VBIOS просит 1595. Проба
источника на его карте: код 2 / подвыбор 7 = PLL XBAR2CLK (797 МГц = 1594,7 ÷ 2 на 07). У нас (GF114) в режиме «от PLL»
HUB2CLK тоже = PLL SYS2CLK (1645 при XBAR 1909). Записи NVIDIA: у6 (ноутбук ASUS, GF108, хаб 950 / флаг 1) — то же, 891.

**Как задумано в VBIOS (473 образа Fermi, уровни с флагом 1 у HUB2CLK):** в 429 из 433 число хаба = числу SYS2CLK — хаб едет от
PLL SYS2CLK, и это верно. Исключения: три платы ASUS GF108 (GT 440 06.2011, GT 630, ноутбук у6) — число хаба = XBAR2CLK, а флаг 1
ведёт к SYS2CLK; один образ GF100 (хаб 1451, SYS2CLK 1401). Остальные GF108 (14 образов) ставят хабу флаг 2, и NVIDIA берёт
PLL XBAR2CLK через подвыбор 7 (у MSI GT 440 с теми же числами 1282 / 1595 / 1595 — ровно 1595). Вывод: флаг 1 у хаба на GF108 —
ошибка ASUS; NVIDIA её не исправляла ни в 270.x, ни в 304+/390 (что видно по базе).

**По поколениям.** До Fermi домена хаба нет (GT21x: HCLK, такт дисплея). Fermi: хаб в режиме PLL = PLL SYS2CLK; провод к PLL
XBAR2CLK — только GF108 (init-скрипт VBIOS ставит в источник хаба подвыбор 7; у GF100/GF114 — 0). Kepler/Maxwell: хаб = 1080 от
делителя (флаг 0) во всех образах базы, не идёт ни за XBAR, ни за SYS. Pascal–Turing: ведомый домен таблицы Clocks. Значит,
«хаб от кроссбара» — особенность GF108, а общий принцип — хаб получает своё число из VBIOS.

**Достижимость (перебор всех известных источников: SPPLL 1620, кварц 27/108, опора PCIe 100,9, 280,3; один или два делителя;
свои PLL у GPC/LTC/XBAR/SYS2; у узлов > 7 — PLL SYS2CLK ÷ пост-делитель; у хаба GF108 — PLL XBAR2CLK):**

| лучшая ошибка | пар узел-уровень (из 12551) |
|---|---|
| ≤ 0,1 % | 11154 |
| ≤ 0,5 % | 1329 |
| ≤ 1 % | 62 |
| ≤ 2 % | 4 (GT 440: хаб 1595, ближе 1620 не дать) |
| 2–3 % | 0 |
| > 3 % | 2: GF100 хаб 1451 (ближайшее 1401, −3,45 %); Gigabyte GT 430 хаб 1400 при XBAR 1460 (+4,29 %) |

**Допуск ±2 %, симметрично.** Между 1,57 % и 3,45 % в данных пусто: любой порог 1,6…3,4 % делит случаи одинаково; 2 % — с запасом
над самым большим «законным» отклонением (1,57 %, его же выбирает NVIDIA). 3 % дал бы то же; 5 % принял бы +4,29 % у Gigabyte —
разгон узла сверх таблицы. Если не попадает ничто — берётся ближайшее, но не выше VBIOS + 2 % (для двух образов из 473).
Это не второй допуск, а запрет разгона: ниже — медленнее, выше — сверх того, что проверил производитель платы.

**Правило в драйвере (build-1121c, порядок как у NVIDIA):** для каждого узла — (1) путь по флагу (1 — PLL, даже если делитель
дал бы ровно: GPC 1620 на GF108; 2 — делитель; 0 — делитель, если VBIOS записал его частоту целыми МГц); попал в ±2 % — берём,
даже если другой путь точнее (у5: хаб 1595, делитель 1620 — NVIDIA берёт делитель); (2) не попал — делитель от SPPLL, если он
попадает; (3) не попал и он — PLL (своя / PLL SYS2CLK), а у HUB2CLK затем PLL XBAR2CLK — только если VBIOS при загрузке поставил
подвыбор 7, с самопроверкой счётчиком; (4) ничего не попало — ближайшее не выше VBIOS +2 %, в журнал. Окно lab_in_window
(−3…+2 МГц) — распознавание «частота делителя целыми МГц» при флаге 0, не допуск; остаётся.

**Отличия от NVIDIA по 473 образам:**
| образ | VBIOS хаб | NVIDIA | 1121c |
|---|---|---|---|
| ASUS GT 440 (06.2011), ASUS GT 630 (sasim44) | 1595 / флаг 1 | 1282 (PLL SYS2CLK) | **1620 делителем** (+1,57 %) |
| ноутбук ASUS GF108 (у6) | 950 / флаг 1 | 891 | **950** (PLL XBAR2CLK, делитель не попадает) |
| 3 образа GF108 (MSI GT 440 и др.) | 1595 / флаг 2, XBAR2CLK 1595 | **не записано** | 1620 делителем (+1,57 %) |

Открыто: при флаге 2 и XBAR2CLK = хабу, когда делитель тоже попадает, NVIDIA могла бы взять PLL XBAR2CLK (правило Б 1120e так и
предполагало) — записи такой платы в базе нет; у5 (XBAR2CLK 1620) этого не различает. Проверка на железе: sasim44 — хаб на 0f
1620 делителем; путь через PLL XBAR2CLK живьём — у Q0AL (GT 730, 1400) и на ноутбуке ASUS (если найдётся тестировщик).
