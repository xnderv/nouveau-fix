# GF108 DDR3: порча на верхней частоте — регистры линий разделов памяти (25.11.2026)

Причину порчи данных на 896 МГц нашёл тестировщик (GT 630M, GF108, DDR3; issue #6, комментарии 25.11). Здесь — что он
нашёл, наша проверка по записям и что из этого следует для остальных плат. Инструмент проверки — `lab/db-fbpa-750.py`.

## Слова
- **Раздел памяти** — часть контроллера памяти чипа со своими линиями к микросхемам; у GF108 их два. Регистры первого
  раздела лежат с адреса 0x110000, второго — с 0x111000; запись 0x11x620 значит «0x110620 и 0x111620».
- **Тетрада** — четыре бита, одна шестнадцатеричная цифра. В этих регистрах восемь одинаковых тетрад: по одной на
  группу линий данных.
- **Ремешок** — резисторы на плате, которыми она сообщает чипу, какая память распаяна. По ремешку из таблиц VBIOS
  выбирается своя строка значений.
- **Инициализация по VBIOS** — запись в регистры значений из таблиц VBIOS. nouveau выполняет её при загрузке и при
  каждом пробуждении карты.

## 1. Что нашёл тестировщик
Сверка состояния (наши `lab/trace-memstate.py`, `memstate-dump.py`, `memstate-diff.py`) показала три группы регистров,
где под nouveau стоит не то, что держит NVIDIA. Делением пополам он оставил одну: под nouveau 0x11x620 = 0x33333333 и
0x11x630 = 0x22222222, у NVIDIA — 0x11111111 и 0. С четырьмя записями этих значений перед первым подъёмом память на
896 МГц работает: по его отчёту — 12 переходов из 12, сон и пробуждение, 20 минут под регулятором, обычная загрузка.
Кэш L2, таблица шины XBAR и паузы оказались не нужны. Наша карта (GDDR5) этого проверить не может.

## 2. Наша проверка
Три записи NVIDIA 390.157 с плат GF108 DDR3. «VBIOS» — значение из таблиц для ремешка платы, то есть то, что стоит
под nouveau; «NVIDIA» — что драйвер читает из регистра.

| плата | ремешок | верхняя частота | регистр | VBIOS | NVIDIA | VBIOS со снятым битом 1 |
|---|---|---|---|---|---|---|
| GT 630M | 2 | 896 МГц | 0x11x620 | 33333333 | 11111111 | 11111111 |
| | | | 0x11x628 | 00000000 | 00000000 | 00000000 |
| | | | 0x11x630 | 22222222 | 00000000 | 00000000 |
| GT 630 | 3 | 896 МГц | 0x11x620 | 11111111 | 11111111 | 11111111 |
| | | | 0x11x628 | 33333333 | 11111111 | 11111111 |
| | | | 0x11x630 | 22222222 | 00000000 | 00000000 |
| Quadro 600 | 2 | 793 МГц | 0x11x620 | 11111111 | 11111111 | 11111111 |
| | | | 0x11x628 | 11111111 | 11111111 | 11111111 |
| | | | 0x11x630 | 00000000 | 00000000 | 00000000 |

Девять совпадений из девяти, на обоих разделах: **NVIDIA держит значение VBIOS, в котором снят бит 1 каждой тетрады**
(маска 0x22222222). Другой таблицы нет.

Ещё по этим записям:
- NVIDIA читает три регистра каждого раздела перед каждым подъёмом на верхний уровень и больше нигде (у GT 630M — пять
  чтений, по одному на подъём);
- записи в них нет ни в одном из 35 скриптов памяти трёх плат и ни в одной прямой записи хоста.

База записей: из 8 записей DDR3 в 6 NVIDIA эти регистры пишет, в 2 только читает. Запись nvc1#6
повторяет картину тестировщиков: NVIDIA читает значение VBIOS без бита 1, скрипты ничего не пишут. В 25 записях GDDR5
записи нет ни одной — к GDDR5 правило не относится.

## 3. Откуда правило
Оно есть в открытом коде nouveau для предыдущего поколения (GT21x, `fb/ramgt215.c`): выше 750 МГц в регистрах
0x100760, 0x1007a0, 0x1007e0 маска 0x22222222 снимается, до 750 МГц — ставится. Порог в коде помечен как «выглядит
произвольным». У GF108 те же три регистра переехали в 0x11x620, 0x11x628, 0x11x630. В нашей карте полей оно тоже стоит
([ddr3-field-map.md](ddr3-field-map.md), таблица линий) — как правило для записей в скриптах.

## 4. Почему повтор записи это пропустил
Драйвер NVIDIA перед подъёмом читает регистр и добавляет запись в скрипт, только если бит стоит. Во всех трёх записях
к их началу бит уже снят (первый проход драйвера в запись не попадает), поэтому записи в скриптах нет — и в наших
таблицах повтора её нет. nouveau же при каждой инициализации по VBIOS возвращает значение с битом. Это случай из
[ликбеза](../2026-11-24/replay-primer.md): действия нет в записи, потому что в момент записи состояние уже было нужным.
Карта полей проверяла правило только там, где запись в скрипте есть; отсутствие записи она ошибкой не считала.

## 5. Что из этого следует
1. **Правило для повтора и для генератора DDR3:** перед подъёмом выше 750 МГц снять бит 1 каждой тетрады в 0x11x620,
   0x11x628, 0x11x630 каждого раздела. Правило — маска, чисел платы в нём нет.
2. **GT 630 второго тестировщика:** после инициализации по VBIOS бит стоит в 0x11x628 и 0x11x630. Это то же отличие
   от NVIDIA, что у GT 630M, и первый кандидат в причины его сбоев на 896 МГц. У него были и порча данных, и зависание
   на подъёме; одна ли у них причина, покажет только опыт.
3. **Quadro 600:** в VBIOS бита нет ни в одном из трёх регистров; правка там ничего не меняет.
4. **GDDR5** (наша GF114, GF106 тестировщика) не затронута.

## 6. Чего мы не знаем
- **Обратное направление.** Драйвер 390.157 на трёх платах бит обратно не ставит: на 324 и 135 МГц держит его снятым.
  В записях базы бывает и обратное: nvc1#2 ставит бит на спуске, три записи GF119 ставят его в 0x110628. У
  тестировщика все уровни со снятым битом чисты.
- **Порог.** 750 МГц — число из кода nouveau. По записям: перед подъёмом на 324 МГц NVIDIA регистры не читает, на 793
  и 896 МГц — читает. Возможно, условие задаёт поле VBIOS, а не частота.
- **Смысл бита** (нагрузка линий, согласование, задержка) не известен.

## 7. Следующий шаг
Одна правка в лабораторном модуле: правило маской для всех плат Fermi с DDR3 вместо четырёх чисел одной платы.
Проверить на GT 630M (с числами там уже работает), затем — на GT 630.
