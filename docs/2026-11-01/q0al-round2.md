# Q0AL, GTX 560 (GF114, 10de:1201): первый прогон пакета «только ядро» — 31.10.2026 (логи вне репозитория, round2)

Debian 13, ядро 6.12.113+deb13-amd64; модуль собран lab/tester-build.sh (коммит 7dd2c79), ключи: lab_mem=0, lab_vbios_src=1,
lab_nv_div_late=1, lab_gpc_seq=13, lab_mux_guard=1, lab_pcie=0, без порога напряжения. Память с загрузки — 135 МГц.

**Прогон 1 (16:24 по его времени).** Первый же подъём после загрузки (с состояния POST, делитель ядра A = 1e, 101 МГц) на 0f:
**тайм-аут переключателя делитель → PLL у GPC** (PLL захвачена, coef 0x13f0f; 0x137100 бит 0 не встал). Защита сработала,
переход завершён без GPC на PLL (ядро осталось 50 МГц), тест остановился по правилу на строке WARNING — так и задумано.

**Прогон 2 (16:30, та же загрузка — dmesg общий).** Первый «0f» ничего не сделал (уровень уже 0f после прогона 1). Дальше
9 переходов подряд без ошибок: 07 → 03 → 0f ×3, ядро 405 / 50 / 850 МГц. Генератор = расчёт и NVIDIA на его карте:
0f — GPC PLL **0x13f0f (63/15, правило «наибольшее M»: первая проверка на железе — работает)**, ROP/hubk07 0x1310b (1804),
hubk06/hubk01 на PLL (1620); 07 — все 810 на делителях; 03 — 101,25 / 270 / 270 / 540. Напряжение 1,0125 / 0,9125 / 0,875 В —
как NVIDIA в его записи.

**После тестов система «ненадолго упала»** — логов этого нет (dmesg снят в конце теста, на последнем 0f). Карта оставалась
на 0f с памятью 135 МГц — сочетание, которого у NVIDIA не бывает (у нас под нагрузкой при 135 МГц GR голодает).

**Что это значит.** Ядро на чужой GF114 вычисляется из VBIOS верно, включая правило M. Слабое место — подъём делитель → PLL
(как два случая в нашем 66б); здесь — с состояния POST (A = 1e), прямо на 0f. Кандидаты (по одному): переход через 405 перед
PLL, как NVIDIA (lab_gpc_pre405); ожидание по таблице 8 / 4,5 мкс вместо признака; повтор в защите и на подъёме.
Спросить у Q0AL: что значит «упала» (зависание, перезагрузка, чёрный экран), есть ли журнал прошлой загрузки
(`journalctl -k -b -1`, если журнал хранится на диске).

## «Бонус»: GT 730 (GF108, 10de:0f02, EVGA 3842:2739), 31.10 16:46 по его времени (логи — ~/Home/stand-2011/q0al-gt730/round1)
Тот же пакет «только ядро» (по ошибке на этой карте). **3 цикла и финальный 0f без ошибок**, 10 переходов `done ret 0`, без
тайм-аутов; система после теста не падала. Ядро 699 / 405 / 50 МГц; напряжение 1,1 / 0,9 / 0,88 В. Генератор: 0f — GPC и hubk07
на PLL 1399,1 (0x1260b), hubk06 PLL 1099,3 (0x11307); 07 — всё 810 на делителях; 03 — 101,25 / 270 / 270 / 540. Строк ошибок
в журнале 5 — все до теста: PRIVRING-чтение 0x139060 при загрузке (наш снимок lab_boot_snap читает регистр GF114, которого у
GF108 нет — безвредно, поправить) и DATA_ERROR Xwayland (класс 9197, к частотам не относится).

**Главное: на этой карте есть тот самый крайний случай.** Таблица 0f: hubk01 = 1400 МГц с флагом 2 («только делитель»), а
делитель hubk01 даёт 1620 или 1080. Генератор поставил **1620 (+16 % к таблице)**. NVIDIA на трёх других GF108 в той же
ситуации переводит hubk01 на источник 2 (db-core-check.md, «Исправление 31.10»). Короткий тест прошёл, но hubk01 четыре раза по
~20 с работал на 16 % выше, чем задумано. Запись NVIDIA 390 с этой GT 730 показала бы, что такое источник 2 на самом деле.
