# Откуда ожидание в скобке: ступенчатое замедление по поколениям (01.11.2026, класс Г + Д)

Вопрос автора 01.11: зачем ожидание, мы теперь знаем (di/dt, node-atlas.md); откуда берутся значения 8 / 4,5 / ~18 / ~150 мкс?
Версии автора: (А) зашиты в драйвере по чипу — искать в открытом коде Tegra; (Б) считаются из VBIOS — искать таблицы и
регистры рядом с питанием; (В, 01.11) у Fermi есть предок того, что дальше стало ступенчатым замедлением, а таблица DI/DT
в новых VBIOS задаёт задержку на каждой ступени.

## 1. Таблица DI/DT в VBIOS
- Документ NVIDIA «BIOS Information Table» (open-gpu-doc) перечисляет указатели BIT 'P' v2 по порядку. 25-й указатель
  (+0x60) — «DI/DT Table Pointer», без описания содержимого.
- У Fermi таблица 'P' длиной 0x30, то есть 12 указателей: Performance, Memory Clock, Memory Tweak, Power Control (напряжение),
  Thermal Control, Thermal Device, Thermal Coolers, Performance Settings Script, CVB, Ventura, Power Sensors, Power Policy.
  **Указателя DI/DT нет.**
- По образам базы:

| поколение | таблица DI/DT |
|---|---|
| Fermi, Kepler | нет (таблица 'P' короче) или указатель 0 |
| GM107, GM108 (4 платы, в т. ч. мобильная) | версия 0x10, 5 записей по 5 байт, **одинаковая на всех платах** |
| GM20x | версия 0x10, все нули |
| Pascal GP102/104/106/107 | версия 0x20, 32 записи по 9 байт, все нули |

  В заполненной таблице GM107/GM108 нет ни длительности ступени (0x40), ни кодов ступеней. Содержимое не расшифровано.
- Performance Settings Script у Fermi трогает только память (0x110000–0x113fff), регистров PTHERM в нём нет.

## 2. Ступенчатое замедление в init-скриптах VBIOS (все образы базы, Fermi … Pascal)
| поколение | 0x020130 | ступени 0x0202c0 / c4 / c8 / cc | 0x0203c0 clk_timing |
|---|---|---|---|
| Fermi | 8107030a / 040a / 060c (мобильные) | **нет** | нет |
| Kepler GK104/106/107 (2012) | 8107040a / 040f / 060c | **нет** | GK104/GK106: 0x10000 (бит 16 grad_slowdown) |
| Kepler GK110/GK208 (2013) | **8107140a** / 140f | 1 / **0x40** / 12182040 / 3efbef9e | GK110: 0x10000 |
| Maxwell, Pascal | 8107140f | то же (у GM204 0x0202c0 = 0xd) | 0 |

- Таблица ступеней (код = 2 · делитель − 2, как в nvgpu): /1, /1,5, /2, /4, /10, /16, /32, /32 …
- Длительность ступени 0x0202c4 = 0x40 — **один регистр на все ступени**, одно значение на всех платах. Единицы неизвестны.
  NVIDIA для Tegra K1 пишет 32: nvgpu gk20a с R24.2.3; в R21.5 этого кода нет.
- Бит 12 (0x1000) в 0x020130 появляется **ровно вместе** с таблицей ступеней.
- У GM107 те же записи NVIDIA делает в записи трассы одним блоком, по скрипту VBIOS.

## 3. Что NVIDIA делает перед переключателем 0x137100 (записи из базы)
- **Fermi, 304+ / 390.** Скобка с хоста: FSRM 0x020160/0x0201a0, CTRL_1, чтение 0x020130 и 0x020144, затем ожидание по
  таймеру и переключатель.
- **Kepler GK104.** Скобки с хоста нет. Хост читает 0x020130 и 0x020144, дважды читает таймер, затем пишет сообщение в
  очередь PMU (0x10a1c0/1c4, голова 0x10a4a4) и только потом делитель 0x1371d0 и переключатель. Замедление на время смены,
  похоже, ушло в прошивку PMU. Её мы смотрим только как чёрный ящик: что в неё отправили и что из этого вышло.
  **Ожидание по таймеру после чтения 0x020130 осталось:**

  | плата | 0x020130 | ожидание |
  |---|---|---|
  | GK104, настольная | 040a | 1,9 < T ≤ 2,1 мкс |
  | GK107, настольная | 040f | ≤ 2,4 мкс |
  | GK107, мобильная | 060c | 4,3 < T ≤ 6,0 мкс |

  У большинства записей шаг таймера 30–45 мкс, и они дают только верхнюю границу. Мобильная группа ждёт дольше — как у
  Fermi, но время в разы короче.
- **Maxwell GM107.** Ни скобки, ни ожидания перед переключателем: ступени включены init-скриптом, остальное делает железо.

## 4. Вывод по версиям
- **(А) в драйвере.** Так на Tegra: VBIOS нет, NVIDIA пишет ступени и длительность 32 в своём коде. На настольных картах
  с GK110 те же параметры лежат в init-скрипте VBIOS и одинаковы на всех платах — константа поколения, а не свойство платы.
- **(Б) из VBIOS.** У Fermi из VBIOS только группа 0x020130, которую пишет devinit. Таблицы ступеней нет: регистры 0x0202c0…
  на GF114 читаются нулями (28.10), замедление включается одним шагом за ~2,2 мкс (24.10). Ожидание NVIDIA идёт по группам
  0x020130; формулы нет.
- **(В) DI/DT — задержка на ступень.** Не подтверждается.
  - Длительность ступени — один регистр, и пишет его init-скрипт, а не таблица DI/DT.
  - DI/DT заполнена только у GM107/GM108, одинаково на всех платах; у GM20x и Pascal она пустая, хотя ступени там включены.
- **Общая мысль (В) подтверждается.** Фиксированное ожидание Fermi — программная замена того, что дальше сделали в железе:
  - Kepler GK104 (2012) убирает скобку с хоста;
  - GK110 (2013) получает аппаратную таблицу ступеней с длительностью;
  - бит 12 в 0x020130 появляется вместе с ней.

  У Fermi железа для ступеней нет, поэтому драйвер замедляет одним шагом и ждёт.

### Разбор всех точек и кандидаты формулы (02.11, до новых перезагрузок)
Точки по записям NVIDIA 390 и базы (F — глубина замедления в скобке, b1/b0 — байты 1 и 0 у 0x020130):

| карта | 0x020130 | F | T, мкс |
|---|---|---|---|
| наша GF114, GPC | 0a, b1 = 3 / 4 / 6 | /6 | 3,65–5,06 / 7,33–8,48 / 25,73–26,69 |
| наша GF114, hub | 0a, b1 = 3 / 4 / 6 | /2 | 1,79–3,42 / 3,65–5,09 / 6,85–7,04 |
| GF110 1080, GPC и hub | 040a | /2 | 3,74–5,44 (как наш hub при /2) |
| GF110 1086, GPC | 040a | /6 | 7,10–8,29 (как наш GPC) |
| GF106 rox4d | 030a | /2 | 16,9–21,0 — **не ложится** (у нас 030a /2 = 1,8–3,4) |
| мобильные GF108M | 060c | /8 | ~150 |
| Kepler GK104 / GK107M | 040a / 060c | скобки нет | ~2 / 4,3–6,0 |

- **Важно отличие GF106.** GF110 с /2 ждёт как наш хаб с /2, значит в формулу входит F, а домен (GPC или hub) — нет. GF106
  выпадает: NVIDIA на нём идёт другой веткой кода — не читает 0x020144, читает таймер 64-битно (nvidia-wait.md §2).
  Значит, в формулу, скорее всего, входит **0x020144**: его NVIDIA читает в каждой скобке на GF114/GF110. У нас он
  = 0x00020080 и его никто не пишет: devinit Fermi его не трогает, Kepler пишет 0x10000 или 0x20080. По виду это та же
  раскладка, что у 0x020160: биты 16–21 — код делителя (2 = /2), бит 7 — включено.
- **Кандидат 1:** T = k(F) · 2^b1 + c(F). Сходится со всеми шестью нашими интервалами:
  - GPC: k ≈ 0,4, c ≈ 1,1 мкс;
  - hub: k ≈ 0,064–0,071, c ≈ 2,5–2,9 мкс.
  Отношение k ≈ 6 при отношении F = 3 — пока необъяснимо.
- **Кандидат 2:** GPC растёт геометрически, ×1,8 на единицу b1, хаб — почти линейно. По трём точкам кандидаты 1 и 2 не
  различить.
- Из открытого кода Tegra точку взять нельзя: nvgpu только ставит биты 31 и 24 (`|=`), младшие байты не трогает.

**Опыты, которые различают версии** (каждый ~15 мин с двумя перезагрузками; сценарий уже умеет `E17=…` и `E17_144=…`):

### Проверка формулы по записям базы и тестировщиков (02.11)
**У NVIDIA два пути кода** (сканирование всех записей Fermi в базе):
- GF100, GF104 (старые записи), GF106, GF108 — 0x020144 **не читает**;
- GF104 (поздние записи), GF110, GF114, GF116, GF117, GF119 — читает, и везде значение 0x00020080.

Коды замедления NVIDIA от 0x020130 и 0x020144 не зависят: во всех наших проходах GPC 0xa (/6), hub 2 (/2).

**Путь без 0x020144 (GF10x): T = 2^(b1+6) тактов кварца 27 МГц**, без зависимости от домена и глубины замедления:

| плата | 0x020130 | расчёт | измерено |
|---|---|---|---|
| GF106 rox4d | 030a | 18,96 мкс | GPC 16,9–21,0, hub 17,3–19,8 — GPC и hub равны, как и требует формула |
| GF108M (0de9) | 060c | 151,7 | 146–161 |
| GF108M (0df4) | 060c | 151,7 | 120–215 |
| GF104 | 030a | 18,96 | ≤ 25 (грубо) |

**Путь с 0x020144 (GF11x): T ≈ код · 2^b1 тактов 27 МГц + C**, где код — код глубины замедления домена (0xa = /6 → 10;
2 = /2 → 2). C ≈ 2,3–2,5 мкс при бите 7 в 0x020144 и ≈ 1 мкс без него.
- Наша карта, GPC, b1 = 2…7: расчёт 3,8 / 5,3 / 8,2 / 14,2 / 26,0 / 49,7 — всё в интервалах, кроме b1 = 3 (на 0,2 мкс выше).
- Наша карта, hub: 2,7 / 3,0 / 3,6 / 4,8 / 7,1 / 11,9 — в интервалах, на краях ±0,1 мкс.
- GF110 1086 (GPC /6): 8,2 при измеренных 7,10–8,29.
- GF110 1080 (/2): 3,6 при 3,74–5,44 (на 0,1 мкс ниже).
- GF114 1205: 8,2 / 3,6 — в интервалах.

**Не проверено:**
- GF100: в записях базы цикла ожидания нет — старый драйвер.
- GF116 и GF119: в записях нет скобок с циклом таймера.
- Kepler: скобки с хоста нет, ~2 мкс при 040a — формулы для него не выводили.
- Откуда точно C (в пределах ~0,2 мкс) — не выяснено.
- **Q0AL, GTX 560 (GF114, 040a, запись 29.10)** — GPC 7,74–8,00 мкс, hub 3,84–4,03 мкс. Расчёт 8,2 / 3,6: GPC на 0,2 выше, hub
