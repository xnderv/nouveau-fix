# Модель: как драйвер NVIDIA управляет частотами Fermi (GF114). Учебник, версия 0.2 (26.10.2026, вечер)

**Что это.** Модель, а не пересказ трасс: по таблицам VBIOS и правилам ниже можно **предсказать**, что драйвер NVIDIA
поставит на каждом уровне и в каком порядке это сделает. Проверено на одной карте — Gigabyte GV-N560OC-1GI (1458:3515):
предсказания сверены с записями драйвера NVIDIA 390, а необходимость шагов — опытами (тесты 1–56). Работающий драйвер для
этой карты (`lab/`, `daily/`) — частный случай модели.

**Как читать.** У каждого утверждения — уверенность и источник.
- **Уверенность:**
  - **опыт** — включали и выключали, разница есть;
  - **вывод** — следует из нескольких фактов или открытого кода;
  - **видно** — есть в записи, «зачем» не проверено;
  - **гипотеза**.
- **Источник:**
  - **А** — наша запись драйвера NVIDIA;
  - **Б** — наш опыт;
  - **В** — VBIOS;
  - **Г** — открытые источники (nouveau, envytools, nvgpu, открытый код NVIDIA для Tegra);
  - **Д** — чужие наблюдения, проверенные нами.

Выводы из декомпиляции не используются ([правило](../provenance.md)).

**Где подробности:**
- [карта понимания](../2026-10-25/core-reclock-map.md) — разбор и опыты;
- [nvidia-logic.md](../2026-10-24/nvidia-logic.md) — правила по записям;

**Покрытие (26.10, вечер).** При смене уровня NVIDIA пишет в 155 регистров, которые относятся к модели. В версии 0.1 их
было 167; разбор записи показал, что ещё 12 записываются не при смене уровня, а при запуске программ и при остановке
драйвера в конце записи, — они теперь служебные:

## 1. Состояние: дерево тактов и уровни

```
кварц 27 МГц ─► SPPLL0 1620 ─┬─► делитель опоры (0x137140+i·4) → 405 ─► PLL узла (0x137000+i·0x20) ─┐
                             ├─► основной делитель 0x1371d0+i·4 (GPC, ROP, hubk07) ──────────────┤─► переключатель 0x137100 ─► пост-делитель 0x137250+i·4 ─► узел
                             └─► (hubk06, hubk01: 1620 напрямую) ──────────────────────────────────┘
             SPPLL1 1620 ─► делители памяти (0x137310, поле B) → 135 / 324;  опора 405 → REFPLL → MPLL → 2004,75
делитель: частота = 1620 · 2 / (поле + 2); у основного делителя действует поле A (биты 0–5), если бит 8 источника = 0
```
Имена у NVIDIA (открытый код для Tegra, **Г**):
- 0x137000 — GPCPLL_CFG;
- 0x137100 — SEL_VCO (PLL или bypass);
- 0x137250 — GPC2CLK_OUT (BYPDIV 0–5, VCODIV 8–13).

**Что тактируют узлы** (документация envytools, `docs/hw/pm/gf100-clock.rst`, **Г**):
- idx 0 — GPC;
- idx 1 — ROP;
- idx 2 («hubk07» в nouveau) — **кросс-бар XBAR** между GPC и ROP. Поэтому NVIDIA переключает его вплотную к памяти;
- idx 7 («hubk06») — **главный такт логики карты** (NVPLL);
- idx 8 («hubk01») — по догадке envytools, **такт VM**: TLB и разбор таблиц страниц;
- idx 9 — **HUB**: общая часть графического движка и копировщики;
- idx 0xc — PMU (PDAEMON), idx 0xe — видеодекодеры.

**Скобка FSRM** (rnndb, доклад M. Peres на XDC 2013, **Г**). Frequency-Switching Ratio Modulation — замедлитель такта
домена. Он делит такт и может выдавать любую частоту между исходной и делённой. В скобке NVIDIA ставит DIV2 = 10 для GPC и
2 для hubk06 при нулевой модуляции. По формуле rnndb это **1/6 такта GPC и 1/2 такта hubk06** на время смены источника.

**Входы модели из VBIOS** (**В**):
- таблица уровней (perf, BIT 'P'): частота узла, 14 бит, **целые МГц**;
- флаги частоты (биты 14–15) и байт 1 записи уровня;
- пределы PLL;
- таблица напряжений и линии VID в GPIO;
- скорость PCIe уровня;
- init-скрипт: состояние при включении, в том числе PMU 202,5, PLL hubk06 1645,3, PTHERM в покое, 0x020130.
  Разобрано 26.10:
  - значения покоя FSRM: 0 / 0x82 / 0x80 / 0x80, FSRM_4 = 0x4040;
  - CTRL_1 = 0x110068;
  - 0x020130 = 0x8107040a;
  - тепловые значения 0x66 / 0x69 / 0x6c, то есть 102 / 105 / 108 °C, в 0x0204c0 / 0x0204d8 / 0x0204e0 (что какое из них
    значит — гипотеза);
  - значения **входа** в скобку в VBIOS нет: это постоянные драйвера.

## 2. Правило: какие значения будут на уровне

### 2.1. Источник узла: делитель или PLL (**вывод** + **опыт**)
1. **Цель** — число из таблицы VBIOS. Это **целые МГц**, у настоящей частоты могут быть дробные (101 = 101,25).
2. **Делитель**, если 1620 · 2 / (n + 2), при нужде с пост-делителем, попадает в окно **−2…+3 МГц** от цели. Это правило
   nouveau для предыдущего поколения (gt215.c, **Г**). На всех узлах нашей карты оно даёт ровно выбор NVIDIA.
3. **PLL — только если делитель не достаёт:** выше 1620 или нецелая доля.
4. **У GPC раскладка NVIDIA:** основной делитель /2 (A = 02, 810), остальное — пост-делителем. Тогда 03 ↔ 07 — смена одного
   пост-делителя, переключатель не двигается.

Почему не «ближе любой ценой», как в gf100.c nouveau: оно ставит GPC на 03 на PLL 100,894 МГц, и уход с этого PLL отказывал
(3 тайм-аута на 54 подъёма, 2 зависания). С правилом — 180 из 180 (тесты 22–24, **опыт**).

### 2.2. Предсказание для нашей карты и сверка с NVIDIA

| Узел | 03 | 07 | 0f | Сверка с записью NVIDIA |
|---|---|---|---|---|
| GPC | 0x1371d0 A = 02, 0x137250 = 0e → 101,25 | A = 02, пост 0 → 810 | PLL 405 × 40 / 9 = 1800; на 0f делитель простаивает на A = 06 (405) | ✅ |
| ROP, hubk07 | A = 0a → 270 | A = 02 → 810 | PLL 405 × 33 / 7 = 1909,3 | ✅ |
| hubk06 | пост-делитель 0a → 270 | 02 → 810 | PLL 1645,3 (ставит VBIOS, не трогать) | ✅ |
| hubk01 | 04 → 540 | 02 → 810 | от PLL hubk06 | ✅ |
| copy, vdec | 16 → 135 | 06 → 405 | 04 → 540 | ✅ |
| хост-домен 0x00e9e0 | 0a → 270 | 06 → 405 | 04 → 540 (= подзапись 7 таблицы) | ✅ |
| PMU 0x137280 | 0e → 202,5 (значение VBIOS, не писать) | то же | то же | ✅ |
| 0x022680, младший байт | 0x1c | 0x14 | 0x14 (= байт 0x0c записи уровня) | ✅ |
| Напряжение | 0,95 В | 0,95 В | 1,075 В (VID по таблице) | ✅ |
| Память | делитель → 135 | делитель → 324 | MPLL 2004,75 | ✅ (скрипты, см. 4) |

## 3. Порядок перехода (алгоритм NVIDIA)

**Подъём** (03 или 07 → 0f). Спуск — те же шаги снизу вверх.

| № | Шаг | Ожидание | Обязательно ли (наша карта) |
|---|---|---|---|
| 1 | Энергосбережение контроллера памяти выкл., дисплей 0x610300 бит 0, PXBAR «переходное» | — | **не видно**, чтобы требовалось: у нас этого нет, а отказов из-за этого не видно ни в одном тесте |
| 2 | Напряжение вверх | **время**, ~195 мкс по таймеру: обратной связи от регулятора нет | порядок «напряжение раньше частоты» — в базе; нужна ли выдержка — не проверено (тест 32 — один прогон) |
| 3 | PCIe → 5 ГТ/с | флаги | в базе; порядок на спуске (`lab_nv_pcie_late`) не критичен (тест 27). Чего мы не делаем: после смены скорости NVIDIA сбрасывает в PCIe DevSta флаг «была исправимая ошибка» (cfg 0x80); у нас он так и стоит. Два своих регистра NVIDIA (cfg 0x644, 0x650) на 2,5 ГТ/с ставит ровно вдвое больше, чем на 5, — похоже на время в тактах линии |
| 4 | hubk06 → PLL (в скобке), hubk01, copy | скобка | скобка — **опыт** |
| 5 | GPC: скобка → путь делителя на 405 → PLL выкл / вкл → захват → переключатель → снять скобку | скобка: **время** у NVIDIA (~8 мкс), у нас **флаг** (~2,1 мкс); захват — **флаг** (бит 17) | скобка — **опыт** (без неё 7 зависаний из 7; без ожидания — зависание, тест 14); «405 перед PLL» — **не обязательно** (тест 25а, 60 из 60 без него) |
| 6 | ROP → PLL | флаг захвата | — |
| 7 | Память: скрипт прошивки PMU | флаги в скрипте, ожидание кадра | **опыт**: через memx nouveau со словами NVIDIA — тысячи переходов |
| 8 | vdec, хост-домен, hubk07 → PLL | флаг | порядок «hubk07 вплотную к памяти» не критичен (тест 28) |
| 9 | Дисплей, PXBAR — обратно; пороги регулятора — в PMU | — | — |

**Спуск: отличия шага 5** (0f → 07):
- скобка → значение пути делителя меняется **за ~2 мкс до переключателя** → переключатель → сразу снять скобку.
  Если подъём был с 07, меняется основной делитель (A 06 → 02). Если с 03 — пост-делитель (02 → 00). Так во всех спусках
  записи try7 (277,02, 329,02, 363,02, 438,18) и в записи t1;
- PLL GPC не выключается;
- у hubk06 и hubk01 пост-делитель ставится до переключателя.

**Запись делителя со сменой значения прямо перед переключателем** (команда) — **опыт**: в плохой загрузке без неё 27
тайм-аутов на 2279, с ней 0 на 2700. **Видно, но не проверено:** пауза 2 мкс между ними (её же делает код NVIDIA для Tegra,
**Г**).

## 5. Что модель пока не объясняет
- **Механизм застревания переключателя** (гипотеза, 26.10). Переключатель «без сбоя» снимает старый такт по его фронту и
  выбирает новый с задержкой. Это общий принцип, см. например патент US 6323715. Значит, **новый такт должен идти** —
  иначе переключение не завершится. Если в плохой загрузке выход простаивающего делителя ядра «стоит» или сбит, а запись
  нового значения его перезапускает, это объясняет и тайм-аут, и лекарство (П6). Проверяется опытами Е1, Е2, Е9.
- **0x020130 и время выдержки скобки** (гипотеза, 26.10). Значение из VBIOS 0x8107040a. Если выдержка = поле + 1 мкс,
  байты 0x07 и 0x04 дают 8 и 5 мкс — ровно в окнах, измеренных у NVIDIA (GPC 7,84…8,51 мкс, hubk06 3,97…5,09 мкс).
  rnndb называет этот адрес иначе (калибровка датчика), так что совпадение может быть случайным. Проверить можно только
  другой картой, у которой в VBIOS другое 0x020130.
- **0x001548** — хост пишет его вокруг каждого шага и никогда не читает:
  - бит 31 — «идёт»;
  - 0x101 — подшаг тактов ядра;
  - 0x102 — ровно время скрипта памяти;
  - 0x104 — hubk01.
  Кто его читает (прошивка PMU?), не видно.
- **Плохие и хорошие загрузки:** застревание переключателя ядра на 60–330 мс в ~1 % спусков. Лечится П6, причина неизвестна.
  Подробно — карта, раздел 4.
- **Как из таблиц VBIOS получаются скрипты памяти.** Скрипты повторяем слово в слово, но не вычисляем. Нужны пары
  «VBIOS + запись NVIDIA» других карт.
- **Смысл флагов VBIOS** (биты 14–15, байт 1) — нужны таблицы других карт.
- **Энергосбережение в простое, PXBAR, 0x001548, часть PCIe** — значения видим, назначение — нет. Раздел «PCIe
  (конфигурация)» в покрытии почти пуст.
- **Общность:** всё проверено на одной карте.

## 6. Как модель проверять и расширять
- **Чужие карты уже сейчас:** таблицы уровней ещё трёх чипов (GF119M, GF108M) из отчётов пользователей подтверждают П1 и
  дают два проверяемых предсказания — [other-cards.md](other-cards.md) (класс источника **Д**).
- **На этой карте:** опыты Е0–Е9 из карты понимания. Каждый подтверждает или опровергает правило из таблицы раздела 4.
  Статусы регистров обновляются в `registers.tsv`, покрытие пересчитывается.
- **На других картах:** модель по их VBIOS предсказывает таблицу раздела 2.2 и порядок раздела 3. Сверка — по их записи
  драйвера NVIDIA или по снимку регистров на каждом уровне. Совпало — правило общее; нет — частное.
- **По версиям драйвера NVIDIA:** первая версия с нашей картой — 270.26 (15.02.2011); в 270.41.06 NVIDIA чинила
  «карта перестаёт отвечать при запуске X», чаще на GF104/GF106. Запись старых версий на той же карте покажет, менялся
  ли порядок перехода с 2011 по 2022 год. Что в журнале изменений относится к частотам —
  [nvidia-changelog-270-390.md](../2026-10-26/nvidia-changelog-270-390.md) (класс **Г**). Стенд 10.04 собран 26.10:
  270.26 отказывает на первом графическом контексте (Xid 38, FECS), 270.41.06 даёт те же уровни, что 390; записать 270.x
  на ядре 2.6.32 пока не удалось — [первый вечер](../2026-10-27/stand-2011-first-night.md).
- **Дальше по поколениям** (дальний план): та же модель — основа для изучения подписанных прошивок снаружи
  ([план](../2026-10-26/provenance-and-research.md), часть 7).
