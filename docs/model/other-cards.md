# Другие карты Fermi: что видно в чужих отчётах и что предсказывает модель (26.10.2026)

**Источник — класс Д**, чужие наблюдения, нами не проверены. Это отчёты пользователей в трекере
`Twilight0/nouveau-dkms`, прочитанные по правилу [provenance.md](../provenance.md):
- только сообщения других людей;
- без сообщений и цитат автора проекта;
- без подписей, которые ставит его диагностическая программа.

Таблицы уровней здесь — то, что сам nouveau прочитал из VBIOS их карт (`/sys/kernel/debug/dri/*/pstate`).

| Карта, чип, память | Кто, где | 03 (ядро / шейдеры / память, МГц) | 07 | 0f |
|---|---|---|---|---|
| GeForce 410M, GF119M, DDR3 | Bonjour540, issue #2 | — | 270 / 540 / 405 | 573 / 1147 / 800 |
| Quadro NVS 4200M, GF119M | yhaenggi, issue #3 | — | 270 / 540 / 405 | 810 / 1620 / 800 |
| GeForce GT 520M, GF119M, DDR3 | kriho520m, issue #7 | — | 270 / 540 / 405 | 740 / 1480 / 800 |

| **Наша** GTX 560 Ti, GF114, GDDR5 | — | 50 / 101 / 135 | 405 / 810 / 324 | 900 / 1800 / 2004 |

## Что это говорит о модели
- **П1 (нижние уровни — на сетке 1620 / n)** подтверждается на трёх чипах. Все частоты 03 и 07 выше — целые доли 1620:
  - шейдеры 540 = 1620 / 3, 405 = 1620 / 4, 810 = 1620 / 2, 101,25 = 1620 / 16;
  - память 405 = 1620 / 4, 324 = 1620 / 5, 135 = 1620 / 12.
- **У GF119M в VBIOS нет уровня 03** — только 07 и 0f.

## Предсказания, которые можно проверить
1. **NVS 5200M (GF108M), уровень 03:** «101» в таблице = 101,25. Модель предсказывает **ту же ошибку nouveau**, что была у
   нас: правило gf100 «ближе любой ценой» поставит шейдерный такт на PLL ≈ 100,9 МГц вместо делителя.
   - **Как проверить:** строка `LAB calc` или чтение 0x137100 бит 0 на 03 с драйвером, где включена смена частот.
2. **NVS 4200M (GF119M), уровень 0f:** шейдеры 1620 = ровно 1620 / 1. Модель предсказывает, что драйвер NVIDIA оставит
   GPC **на делителе, без PLL** — в отличие от наших 1800 и от 1147 / 1480 у 410M и GT 520M.
   - **Как проверить:** снимок 0x137100 под драйвером NVIDIA на 0f (бит 0 = 0) или запись mmiotrace.
3. **Все GF119M и GF108M: уровень 07** целиком на делителях, переключатель 0x137100 = 0.
   - **Видно уже сейчас:** во всех четырёх отчётах 0x137100 = 0 и PLL ядра 0x137000 = 0x10000 (выключен) на 07. Это
     согласуется с моделью, но снято под nouveau, не под NVIDIA.

## Что ещё интересно
- **kriho520m (GT 520M)** — на том же ядре 7.0.0-38, что у нас. Смена частоты памяти в проекте Twilight0 у него не
  работает. Наш путь (штатный memx nouveau + скрипты NVIDIA из записи именно этой платы) в принципе применим, но нужна
  запись драйвера NVIDIA с его карты.
- **rox4d (issue #9, 26.10)** не может снять mmiotrace драйвера 390.157 на ядре 6.18: в записи только одна поздняя карта
  памяти, без регистрового окна карты. Наш рабочий рецепт — Ubuntu 22.04 с ядром 5.15 и `trace/run-trace.sh`. Главное в
  нём: драйвер NVIDIA выгружается, включается mmiotrace, и только потом драйвер грузится заново. Черновик ответа —
  [`../upstream/twilight0-issue9-reply-draft.md`](../upstream/twilight0-issue9-reply-draft.md).

## GF106 — запись драйвера 390 нашим сценарием (rox4d, 27.10.2026; класс Д, сырые данные проверены нами)

Gigabyte GV-N4500C-1GI (GTS 450, GF106 rev a1), NVIDIA 390 на ядре 6.18, наш `trace/run-trace.sh` (контроль, затем запись;
5,7 млн строк, все фазы). Разбор — [results/other-cards/gf106-rox4d/](../../results/other-cards/gf106-rox4d/) (переходы,
выдержки, пошаговые выдержки; сырая запись не в репозитории). Уровни по nvidia-settings: 0 — 50/135, 2 — 830/1804 МГц.

**Совпадает с GF114 (модель общая для двух чипов):**
- значения регистров нижних уровней: ROP/hubk07 0a/02 (270/810), hubk06 пост 0a/02, hubk01 04/02, copy/vdec 16/06/04,
  пост-делитель GPC 0e/00; GPC main A = 02 — **П1, П2 на втором чипе**;
- порядок перехода: напряжение и память первыми вверх; скобка FSRM у GPC и hubk06; PLL GPC перезапускается внутри скобки
  перед переключателем на подъёме (0x30001 → 0x30000 → 0x10001 → 0x30005); пост-делитель 0e пишется внутри скобки на
  ступени 07 → 03 — **П3, П5, П6 для PLL и пост-делителя**;
- выдержка ~40 мкс вокруг перезапуска PLL на подъёме; регулятор: вверх сразу на 0f, вниз через 07 по ~8 с — **П11**.

**Отличается (частное для карты):**
- код замедлителя в скобке GPC: **0x20082 / 0x2** (1/2), у нас 0xa008a / 0xa (1/6); у hubk06 — 0x20082 / 0x2 на обеих;
- выдержка после входа в скобку на спуске (по чтениям PTIMER): **GPC 16–22 мкс, hubk06 16–22** против наших 7–9 и 4–5;
  цикл опроса таймера у него читает 64 бита (0x009410/0x009400/0x009410), у нас — только 0x009400;
- **шага «405 перед PLL» (П7) нет**: 0x1371d0 за всю запись не пишется, A = 02 с загрузки; спуск 0f → 07 — скобка без
  записи делителя (менять нечего); у нас на 0f делитель стоит на 06 и меняется внутри скобки;
- 0x020130 = **0x8107030a** (у нас 0x8107040a): байт GPC тот же 07 при выдержке 16–22 против 8 — гипотеза «байт + 1 мкс»
  снята; CTRL_1 при загрузке 0x110028 (у нас 0x110068);
- коэффициент PLL ROP/hubk07 0x12b0a (405 × 43 / 10 = 1741,5 МГц; у нас 0x12107 = 1909,3); коэффициент PLL GPC за запись не
  пишется (остался с контрольного прохода).

**Что это даёт.** Значения уровней и порядок шагов — общие для Fermi (двух чипов); код скобки, выдержка и «405 перед PLL» —
свои у карты. Безопасная выдержка не константа семейства: у GF106 она вдвое больше нашей при том же байте 0x020130.
