# Корпус VBIOS GTX 560 Ti (TechPowerUp, по разрешению 28.10): что в нём лежит — часть 1 (В1–В3)

Источник класса В. 147 образов «GTX 560 Ti» из коллекции TechPowerUp (список модели целиком), скачаны 28.10 в
`~/Home/nouveau-archive/tpu-vbios/2026-10-28-gtx560ti/` (manifest.csv: id, файл, SHA256; образы в репозиторий не кладём).
Инструменты: `lab/vbios-survey.py` (таблица уровней, память), `lab/vbios-stats.py`, новый `lab/vbios-devinit.py`
(скрипты инициализации BIT 'I' по раскладке опкодов nouveau, класс Г; статический проход, все ветви).

## 1. В1 — сетка частот: уровни 03 и 07 одинаковы у всех плат, 0f — у каждой платы свой
По 135 платам GF114 (значения таблицы BIT P 0x40, МГц):
- **03**: gpc 101, rop/hubk06/hubk07 270, hubk01 540, copy/vdec 135, host 270, pmu 203, mem 135 — **130 из 130** плат, у
  которых уровень есть; флаги узлов одинаковы (2 = «делитель», 0 = фикс.).
- **07**: gpc/rop/hubk06/hubk01/hubk07 810, copy/vdec/host 405, pmu 203, mem 324 — **135 из 135**.
- **0f**: gpc 1645 ×40 (референс), 1800 ×39 (наша), 1900 ×16, 1760 ×11, 1660/1701 ×8, 2000/1700 ×3, ещё 5 значений;
  rop 1744 ×41, 1908 ×19, 1907 ×11 (наша), 1866 ×11, …; hubk06/hubk01 1645 ×122 (почти константа), 1640 ×6, 1700 ×3;
  mem 2004 ×64 (наша), 2100 ×32, 2052 ×10, 2290 ×9, 2106 ×7, 2000 ×5, …; copy/vdec/host 540, pmu 203 — у всех.
- Байты записи уровня: байт 2 (индекс напряжения) 00/01/02 у всех; байт 0x0b 01 (03/07) и 06 (0f) у 130, 09 у 7.

Вывод: значения 03 и 07 — константы семейства (решётка 1620/n, как в учебнике), 0f — заводская настройка платы (ядро,
ROP, память), при этом hub-такты на 0f почти у всех 1645. Правило «не обобщать по 0f» подтверждено 135 платами.

## 2. В2 — инициализация PTHERM/FSRM: константа семейства, с одним различием по версии VBIOS
Записи devinit в 0x020000–0x020200 у **всех 138** GF114: 0x020000 = c0000000, 0x020008 = c0080000, 0x02000c = 9c43,
0x020010 = fa410392, 0x020074 = 26, 0x020078 = 01100000, 0x020114 = 00b46600, 0x02011c = 00876530, 0x020120 = 241,
**0x020130 = 8107040a**, 0x020160/164/168/16c = 0 / **82** / 80 / 80, **0x0201a0/a4 = 4040**, 0x0201c0…cc = 10000/0/10000/10000.
Различаются только у 9 плат с VBIOS **70.24.0a** (стартовые образы января 2011: Colorful, Galaxy, Gigabyte, KFA2, MSI,
NVIDIA): 0x020004 = 110028 (у остальных 110068), 0x02010c = 49 (у остальных 2), 0x020138 = 3 (у остальных 13), 0x02013c
не пишется. Это различие **версии прошивки**, не платы: внутри 70.24.11 и новее все платы одинаковы.
Контраст GF110 (8 плат): 0x020130 тот же 8107040a, но FSRM-инит другой — 0x020160 = 20000, 0x020164 = 20082, 0x0201a0 = 0.
У GF106 (rox4d) 0x020130 = 8107030a. Итог: 0x020130 и регистры FSRM задаются **чипом** (VBIOS одного чипа пишет одно и
то же), а не платой; код замедления, который драйвер пишет в 0x020160/0x020164 при переключении (0xa008a/0xa у GF114,
0x20082/0x2 у GF106), и выдержка в скобке в VBIOS не появляются — это дело драйвера.

## 3. В3 — инициализация тактов: тоже константа семейства; 0x1371c8/cc, 0x139xxx, 0x137360 devinit не трогает
Записи в 0x137000–0x137400 одинаковы у всех 138 (и у GF110): опора 0x137120/124/128 = 1003/3/3, 0x13713c = 3,
0x137140/144/148/15c = 81200707 → 81200606, главные делители 0x1371d0 = 81201f1f → маской 1e1e (/31 → /30), 0x1371d4/d8 =
81200b0b → 0a0a, 0x137160…198 = 3 (маска fffffefc), 0x13718c = 30000, пост-делители 0x137250/254/258 = 81200000,
0x13726c/270/274/288 = 0b/05/17/17 → 0a/04/16/16, 0x137280 = 81200f0f → 0e0e, 0x137300 = 103, 0x137310 = 81201717 → 1616,
0x137320 = 0 → 103, 0x137330 = 81200000, 0x137340 = 1, 0x1373ec/f0/f8 — по ремешку памяти (ram_restrict, 8 ремешков).
Чего devinit **не пишет** ни у одной платы: 0x1371c8/0x1371cc (их 0x30000 ставит драйвер NVIDIA при загрузке),
0x139060…0x139220 (значение 0x7c в снимках — не из скриптов инициализации), 0x137360, 0x132000/0x132004 (MPLL — скрипты
памяти, не devinit), слова 0x1320e8–0x132124 (в 0x132xxx devinit пишет только 0x132018 = 10009000 → маской 8000 и
копирует бит в 0x132100). Значит, состояние «после POST до драйвера», которое отличало отказы стенда (§15–16 журнала),
скриптами инициализации не задаётся — его создаёт либо аппаратный сброс, либо то, что POST делает вне devinit.

# Часть 2 (28.10 вечер): память (В4), напряжения (В5), особые платы

## 5. В4 — «база платы» и «константы только у нас» в скриптах памяти задаёт devinit по ремешку, и они одни на всё семейство
Карта покрытия `lab/memgen.py` (ремешок 3) делит 314 записей скриптов памяти NVIDIA на формулы (76), константы, общие
со второй картой (171), «только у нас» (9) и «базу платы + управляющие биты» (44). Корпус отвечает на вопрос, откуда берутся
последние две группы: **их пишет devinit** (`lab/vbios-devinit.py`, группы ram_restrict по ремешку памяти), и для ремешка 3
значения совпадают с нашими у **137–138 плат из 138**:

Вывод для генератора: «базу платы» не нужно читать с живой карты — это значения таблиц devinit данного VBIOS по ремешку
памяти, и у всего семейства GTX 560 Ti они одинаковы (отклонения у 1–10 плат — другие ремешки/ревизии памяти). «Только у
нас» — на самом деле константы семейства. Таблицы памяти (rammap + тайминги) у 135 плат образуют 25 различных наборов;
крупнейший (58 плат, включая Asus, EVGA и нашу Gigabyte) байт в байт совпадает с нашим; 15 плат несут наш subsystem id
1458:3515 (Gigabyte GV-N560OC), все с VBIOS 70.24.11/70.24.21.

## 6. В5 — напряжения: одна таблица VID на всё семейство, у платы свой только диапазон на 0f
Новый `lab/vbios-volt.py` (раскладка по nouveau volt.c/vmap.c). Таблица напряжений 0x40 «по диапазону» у **всех 138**:
base 1,2125 В, шаг −12,5 мВ на VID, 32 VID, потолок 1,15 В → 1,15…0,825 В. Карта напряжений (vmap 0x10, 4 записи):
записи 0 и 1 — ровно **0,95 В** (уровни 03 и 07) у всех плат; запись 2 (уровень 0f) — диапазон min–max, свой у платы:
0,9625–1,05 В у 89 плат (референс), 0,975–1,0625 у 11, 0,9875–1,075 у 7, **1,0–1,0875 у 7 (наша)**, 1,0125–1,1 у 7,
0,9625–1,1 у 5, 1,1425–1,23 у 3 (разогнанные), 0,9375–1,05 у 2. Наши 1,075 В на 0f лежат внутри нашего диапазона; то, что
драйвер выбирает внутри диапазона (по температуре: коэффициенты arg записи), остаётся вопросом драйвера, не VBIOS.

## 7. Особые платы и «родня»
- Без уровня 03 (только 07/0f): 5 плат — Manli 110118 и четыре Zotac января 2011 (две пары одинаковых дат).
- Байт 0x0b = 09 встречается только у плат GF110 (7), у GF114 — ни одной.
- Наш 0f целиком (gpc 1800, rop/hub07 1907, hub 1645, mem 2004): ещё 5 плат (Asus 2048 111228, Gigabyte 110331/110928/
  111006/111007); gpc 1800 на 0f — 39 плат.

# Часть 3 (28.10 вечер): В6 — GF106 и GF116 (GTS 450, GTX 550 Ti) против GF114

Выборка тем же путём: GTS 450 — 94 образа (71 GF106 10de:0dc4, как карта rox4d; 23 GF116 Rev. 2 10de:1245), GTX 550 Ti —
65 (все GF116 10de:1244); все 159 с сигнатурой, без недостающих, уникальны по SHA256; архив
`~/Home/nouveau-archive/tpu-vbios/2026-10-28-gts450/` и `…-gtx550ti/` с manifest.csv. Версии VBIOS: GF106 — 70.06.xx (две
волны: 70.06.0f/13 — 45 плат, 70.06.1f и новее — 25), GF116 — 70.26.xx.

## 9. Уровни 03 и 07 одинаковы у всех трёх чипов, 0f — у платы
GF106 (71), GF116 Rev. 2 (23), GF116 550 Ti (65): уровень 03 — gpc 101, rop/hubk06/hubk07 270, hubk01 540, mem 135,
copy/vdec 135, host 270, pmu 203; уровень 07 — все 810, mem 324, copy/vdec/host 405 — **те же числа, что у 135 плат
GF114** (исключения: 2 платы GF106 с mem 270 на 07; платы Rev. 2 с DDR3 — mem 800/667 на 0f). Уровень 0f: GF106 gpc
1566/1700/1620, hub 1566, mem 1804/2000; GF116 550 Ti gpc 1800/1940/1900, hub 1800, mem 2052/2150. Итог: решётка
1620/n на нижних уровнях — свойство семейства GF10x/GF11x, не нашего чипа; 0f везде заводской.

## 10. Инит PTHERM/FSRM: чип задаёт 0x020130, FSRM-инит зависит ещё и от поколения прошивки
| регистр | GF114 (138) | GF110 (8) | GF106 (71) | GF116 Rev.2 (23) | GF116 550 Ti (65) | rox4d (снимок до драйвера) |
|---|---|---|---|---|---|---|
| 0x020130 | 8107040a | 8107040a | **8107030a** | 8107030a | 8107030a | 8107030a |
| 0x020004 | 110068 (0a: 110028) | 110068 | 110028 | 110068 | 110068 | 110028 |
| 0x020160 | 0 | 20000 | 0 | 0 | 0 | 0 |
| 0x020164 | 82 | 20082 | **0 ×45 (70.06.0f/13) / 20082 ×25 (70.06.1f+)** | 20082 | 20082 | 0 |
| 0x0201a0/a4 | 4040 | 0 | 4040 | 4040 | 4040 | 4040 |
| 0x020138 | 13 (0a: 3) | 13 | 0 ×46 / 3 ×25 | 13 | 13 | — |
Снимок rox4d совпадает со старшей волной GF106 (70.06.13): его карта — из первой партии GTS 450. Код замедления
0x20082, который драйвер пишет в 0x020164 при переключении на GF106, в поздних прошивках стоит уже после POST; у GF114 в
инициализации стоит 0x82, а драйвер пишет 0x20082 (hub) и 0xa008a (GPC). Выдержки в скобке (8 мкс у GF114, 16–22 мкс у
GF106 по записям) в VBIOS нет ни у одного чипа — это константа драйвера для чипа.

## 11. Инит тактов: одна схема, другие делители у GF106/GF116
Опора (0x137120…, 0x137140/144/148/15c = 81200707 → 0606), пост-делители 0x137250…, 0x137300/320/330/340 — одинаковы у
всех трёх чипов. Различаются главные делители и делитель памяти, которые POST оставляет: GF114 0x1371d0/d4/d8 =
81201f1f → 1e1e, 0x13726c/270/274 = 0b/05/17, 0x137310 = 81201717 → 1616; GF106/GF116 — 0x1371d0/d4/d8 = 81200303 → 0202,
0x13726c/270/274 = 03/03/07, 0x137310 = 81200909 → 0808 (у rox4d после POST ровно так: 81200202, 81200808). 0x1370e4:
GF114 14110, GF106 13a0f (и 2 платы иначе), GF116 550 Ti 12809. По 0x132xxx и 0x139xxx — то же, что у GF114: devinit
пишет только 0x132018 и копирует бит в 0x132100.

## 12. Напряжения
Таблица VID у всех трёх чипов та же (1,2125 В, −12,5 мВ/VID, 32 VID), потолок разный: GF114 1,15 В, GF106 1,1625 В (57 из
71; у 5 плат 0), GF116 1,15 В. Карта напряжений: уровни 03/07 — 0,9625 В у GF106, 0,95 В у GF116 и GF114; уровень 0f —
диапазон платы: GF106 1,0–1,1375 В (55 из 71), GF116 550 Ti 1,0125–1,125 В (47 из 65), GF116 Rev. 2 1,0–1,15 В (18 из 23).

## 13. Что это даёт модели
Константы семейства (решётка уровней, схема инита тактов, таблица VID) и константы чипа (0x020130, FSRM-инит,
делители после POST, 0x1370e4) теперь разведены по 297 платам трёх чипов. Для П-правил: FSRM-код и выдержка — чип +
драйвер, не VBIOS и не плата; «плохое состояние после POST» на стенде — не из devinit ни у одного чипа. Следующее:
генератор скриптов памяти на devinit-таблицах по ремешку с проверкой на второй карте nouveau; фото плат.
