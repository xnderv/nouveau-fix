## Ключевые находки
1. Сценарий памяти Fermi (`nvkm/subdev/fb/ramgf100.c`) — запись (mmiotrace) с чужой карты, с жёсткими значениями регистров
   вывода изображения: `0x611200 ← 0x3300 / 0x3330`, `0x61c140 ← 0x19240000 / 0x09a40000`.
   **На этой карте реальные значения: `0x611200 = 0x00000031`, `0x61c140 = 0x00000000`.** Восстановление своих значений
   убрало таймауты дисплея → гипотеза частично подтверждена.
2. «Пауза» `0x611200 ← 0x3300` тоже чужая (для нашего 0x31 смысл битов неизвестен) — следующий подозреваемый.
3. Ядро и узлы на 07 переключаются корректно — проблема в шаге памяти.
4. Модуль частот всегда считает температуру 90 °C (`clk->temp`, `nvkm_clk_tstate` никто не вызывает) — влияет только на выбор
   напряжения (с запасом), не на защиту от перегрева.
5. Падение ядра при «шторме» (`nouveau_fence_sync`, use-after-free) — патч Fleury (LKML 2026-07-23) недостаточен.
