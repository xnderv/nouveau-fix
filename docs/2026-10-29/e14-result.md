# Опыт Е14 (тест 61, 28–29.10): глубина замедления GPC в скобке — /2, /6, /8

**Вопрос.** Входит ли глубина замедления FSRM (код idle_factor в 0x020160: NVIDIA ставит /6 на GF114, /2 на GF106)
в условие застревания переключателя и в нужную выдержку.

**Сборка.** Модуль 8ADDE209… (28.10: код по платам, FSRM-код по чипу, ядро 7.0.0-42), ключ lab_therm_gpc_factor:
0 → по чипу (0xa = /6), 2 → /2, 14 (0xe) → /8. База — как у NVIDIA: ожидание по признаку, запас 0 мкс, без команды;
плюс lab_gpc_pre405=1 lab_nv_hubpost=1 lab_nv_pcie_late=1 lab_nv_hub07mem=1 lab_gov_nv=1 lab_mux_guard=1 (отличия от
базы по журналу). Нагрузка — браузер (hangtest), уровни 03 → 0f → 07, сторож и чёрный ящик включены.

**Ход (журнал results/night-20261028-212646.txt, hangtest-20261028-212648/215054/225056/235005.txt):**
| этап | код | подъёмов | тайм-аутов | ошибок GPU | время |
|---|---|---|---|---|---|
| 61о контроль | /6 | 600 | 0 | 0 | 21:26–21:50 |
| 61а | /2 | 1500 | 0 | 0 | 21:50–22:50 |
| 61б | /8 | 1500 | 0 | 0 | 22:50–23:50 |
| 61в контроль | /6 | 300 | 0 | 0 | 23:50–00:02 |

**Итог (класс Б).** Сессия оказалась хорошей (0 на 600 в контроле), поэтому серия шла в режиме GOODRUN: проверялось,
не портит ли смена глубины хорошую сессию. Не портит: 0 тайм-аутов и 0 ошибок GPU на 3900 подъёмах при /2, /6 и /8.
При /2 ядро в скобке идёт на 900 МГц вместо 300 — и переключатель не застрял ни разу. Значит, в хорошей сессии глубина
замедления в условие не входит, и «безопасность» скобки — не в том, насколько медленно идёт такт. Вопрос, меняет ли
глубина частоту застреваний в ПЛОХОЙ сессии (где контроль даёт тайм-ауты), остаётся открытым: нужен тест 61 без GOODRUN
в плохой загрузке. Побочный результат: модуль с кодом по платам на нашей карте под 7.0.0-42 — 3900 подъёмов без
отклонений от прежнего поведения.
