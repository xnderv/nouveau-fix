# Ответ rox4d в xnderv/nouveau-fix#1 — опубликован 29.10.2026 20:17 MSK: https://github.com/xnderv/nouveau-fix/issues/1#issuecomment-6503490914

Отлично, модуль собрался и плату узнал («LAB: плата GF106 GTS 450 … 135/324/1804 МГц») — это главное. Последняя строка —
это сработала защита в скрипте: он остановился до первого перехода, с картой ничего не делалось, она в состоянии после POST.

Причина — параметры модуля не применились: у тебя nouveau грузится из initramfs (на 2-й секунде), а в моей инструкции
`update-initramfs` стоял раньше, чем добавление файла с параметрами. Моя ошибка, извини.

Проще всего выставить их прямо сейчас, без перезагрузки (все параметры доступны на запись в sysfs):

```
sudo sh -c 'cd /sys/module/nouveau/parameters && echo 14 > lab_mem_replay && echo 1112500 > lab_volt_min_uv && echo 0 > lab_pcie && echo 0 > lab_clk_mmu_lock && echo 1 > lab_gpc_div && echo 1 > lab_pmu_div && echo 1 > lab_mux_guard && echo 16 > lab_therm_wait_us'
```

и снова `sudo bash lab/rox4d-test.sh`. Первый переход после загрузки по-прежнему должен быть на 0f — ты ещё ни одного не
делал, так что всё в порядке.

Два новых параметра по сравнению с моим первым письмом — по результатам последних двух дней:
- `lab_mux_guard=1` — если переключатель источника частоты не сработает вовремя, драйвер повторит переключение (до трёх раз),
  а не будет ждать; у нас без этого такие случаи заканчивались зависанием;
- `lab_therm_wait_us=16` — дополнительное ожидание внутри «скобки» замедления перед переключением. По твоим записям драйвер
  NVIDIA на GF106 ждёт ~18 мкс от входа в скобку, а наш драйвер по умолчанию переключает сразу после внутреннего флага
  (~2 мкс). На нашей карте в «плохих» загрузках раннее переключение иногда застревает; 2 + 16 ≈ 18 мкс — как у NVIDIA.

Чтобы параметры держались после перезагрузки: файл `/etc/modprobe.d/nouveau-lab.conf` со строкой

```
options nouveau lab_mem_replay=14 lab_volt_min_uv=1112500 lab_pcie=0 lab_clk_mmu_lock=0 lab_gpc_div=1 lab_pmu_div=1 lab_mux_guard=1 lab_therm_wait_us=16
```

затем `sudo update-initramfs -u` и перезагрузка.
