# Скрипты памяти: NVIDIA на нашей карте против nouveau и таблиц VBIOS (24.10, этап 1)

Зачем: патч 0010 переключает память, проигрывая пять скриптов PMU, которые драйвер NVIDIA загрузил на этой карте. Это
работает, но только на плате 1458:3515. Для других карт GF114 нужен генератор: каждую запись надо отнести к одной из групп —
общая для всех, посчитана из VBIOS, особенность платы или дисплея, неизвестно.
Инструменты: lab/nv-memscr-decode.py (скрипты → операции), lab/vbios-mem.py (таблицы памяти VBIOS).

## 1. Главное

1. **Сценарий памяти nouveau (`ramgf100.c`, `gf100_ram_calc`) сам — запись скриптов PMU NVIDIA с другой карты.** В его
   комментариях лежат сырые слова тех же скриптов (`// 0x00020034 // 0x0000000a`, `// 0x00030014 // 0x00000000 //
   0x02b5f070` — у нас это операции 0x34 и 0x14 «ждать кадр»). Метод тот же, что у нас, только карта чужая.
2. **У nouveau две ветки, у NVIDIA пять скриптов.** Ветка nouveau «делитель» (mode 0) почти слово в слово — скрипт NVIDIA
   **«324 → 135»** (E): тайминги 0x10f290 = 0x02060505, 0x10f29c = 0x0000114c, 0x10f2a0 = 0x42e10069 (у NVIDIA те же),
   0x10f294 — 0x34208288 против 0x34208287, делитель 0x137310 = 0x81201616 (= 135). **Значит, nouveau на любой уровень с
   делителем пишет тайминги и делитель для 135 МГц.** Отсюда находка 20.10: «на 07 карта показывает 135 вместо 324».
   Ветка «MPLL» (mode 1) — скрипт «324 → 2004» с чужой карты: тайминги другие (0x0b343825 против наших 0x0c3c362a).
3. **nouveau ищет в VBIOS запись таймингов для нужной частоты, но не использует её** (`timing.data` в `gf100_ram_calc`
   вычисляется и дальше не читается); все значения прошиты числами.
4. **Тайминги NVIDIA считаются из таблицы VBIOS** — формулы найдены и сходятся на трёх частотах (раздел 3).

## 3. Формулы, найденные по трём частотам
- **0x10f290 = RP << 24 | (2·RAS) << 16 | RFC << 8 | RC** — точно на 135, 324 и 2004. Это формула nouveau для Tesla
  (`nv50_ram_timing_calc`, timing[0]), только поле RAS у Fermi удвоено.
- **0x10f300 = MR0 GDDR5** по формуле nouveau `nvkm_gddr5_calc`: WL | (CL − 5) << 3 | (WR − 4) << 8 → 0x115 на 135/324
  (CL 7, WR 5, WL 5), 0xa4d на 2004 (CL 14, WR 14, WL 5) — точно. Откуда WL = 5 — пока не найдено (в таймингах CWL = 0).
- **0x10f29c байт 1 = 2·t20 + 1** — точно на трёх частотах (0x11 / 0x19 / 0x21), остальное постоянно (0x4c).
- **0x10f294 байт 0 = 0x80 | CL** — точно на трёх; байт 3 постоянный (0x34); байты 1–2 — не разобраны (0x82/0xc2/0x82, 0x20/0x20/0x93).
- **0x10f298 = 0x44 << 24 | WR << 16 | WTR << 8 | ramcfg[7]** — сходится на двух частотах (324, 2004), кандидат.
- **0x10f2a0** — 0x42e?0069: младший полубайт байта 2 = ODT + 1 (1 / 1 / 2), бит 0x8000 только на 324 — не разобран.
- **Режимные регистры GDDR5 — номер MR в битах 20–23 значения:** 0x10f330 = MR1, 0x10f338 = MR3, 0x10f340 = MR5,
  0x10f344 = MR6, 0x10f348 = MR7. Совпадения с формулами nouveau (`nvkm_gddr5_calc`, сделана для Kepler, ramcfg 0x11):
  MR3 бит 5 = «частота < 1000 МГц» (0x120 на 324, 0x100 на 2004) ✔; MR5 бит 2 (LP3) ставится в конце — у NVIDIA 0x500000,
  потом 0x500004, как в nouveau gk104 («LP3 later») ✔; MR7 биты 7 и 3 (vh, lf — «низкая частота») стоят на 324 (0x088) и
  сняты на 2004 ✔ по смыслу; MR6 бит 0 (pd) — 1 на 324, 0 на 2004. Входы для MR1/MR6/MR7 у Fermi лежат в ramcfg версии
  0x10 — раскладка её полей под эти биты ещё не найдена (nouveau умеет только 0x11).

## 4. Регистры по группам (все записи пяти скриптов)
Сокращения скриптов: A 135→324, B 324→2004, C 2004→324, D переобучение на 324, E 324→135.

**Одинаковы во всех скриптах и в nouveau** (общий порядок шага, не зависят от карты): 0x132100 = 1, 0x10f990 = 0x20012001,
0x100b0c 0x80012 → 0x80028, 0x10f210 0 → 0x80000000, 0x10f310 = 1, 0x10f314 = 1, 0x10f090 0x61 → 0xc000007f → 0x4000007e,
0x13d8f4 = 0, паузы 1000/2000 нс.

**Зависят только от направления (с делителя / с MPLL), одинаковы у NVIDIA и nouveau:** 0x10f988/98c/998 (0x20010000/0/0x10a00
на делителе, 0x2004ff00/0x3fc040/0x11a00 перед MPLL), опорный PLL 0x10fe20 (0x20010000 → 0x20010001 → 0x20010005),
0x132000 = 0x18010101 (MPLL вкл) / 0x18030001.

**Отличаются, значение — из VBIOS** (раздел 3): 0x10f290, 0x10f294 (байт 0), 0x10f298, 0x10f29c, 0x10f300 (MR0), MR3, MR5;
коэффициенты PLL памяти 0x10fe24 = 0x1160f (у nouveau — считаются `gt215_pll_calc`), 0x132004 = 0x11b08 (так же);
делитель 0x137310 (0x81200816 на 324, 0x81201616 на 135, бит 27 на MPLL) — у nouveau всегда 135.

**Отличаются, источник не найден** (кандидаты на особенности платы или на поля ramcfg 0x10):
0x10f808 (0x48020050 на 135, 0x7aa20050 на 324, 0x7aaa0050 на 2004), 0x10f824 (0x7877 / 0x7e76 / 0x7e77 / 0x7fd4 / 0x7e54),
0x10f830 (0x08100017 и т. д.), 0x10f610/614 (0x40044f77 / 0x40044e77, на A ещё 0x20044e77 → 0x20044f77), 0x10f604
(0xf0000020 / 0xf1000020), 0x10f200 (0x008f… у NVIDIA, 0x00ce… у nouveau — разные карты), MR1 0x10f330, MR6 0x10f344,
MR7 0x10f348, 0x100c00 (0x0c000124 / 0x04000124), 0x10f870 (0x99999999 / 0), шаблоны обучения 0x10f628/62c/630/634/640/644,
0x110644…0x113644 = 0x66666666, 0x10fb04/08 = 0x55550000, 0x10fc20…0x10fc74 = 5 (только E), 0x10f828 = 0x300000 (только A),
GPIO 0xe280 = 0x34000076 (A) и 0xe108 = 0x7064f / 0x7034f (B, C) — линии напряжения памяти.

**Только в nouveau (с чужой карты), у NVIDIA на нашей нет:** 0x61c140 = 0x19240000 / 0x09a40000 (дисплей той карты; у нас
0 — из-за этого были тайм-ауты дисплея 20.10), 0x611200 как абсолютное 0x3300 (у NVIDIA на нашей карте тоже 0x3300/0x3330 —
совпадает, но nouveau пишет его числом, а не относительно текущего), 0x1373ec = 0x20404 / 0x30404 (у NVIDIA 0x20f0f / 0x30000).

**Операции скрипта, которых нет в memx nouveau:** 0x34 (арг. 0x0a в начале, 0x0b в конце), 0x39 (0xba / 0x4e / 0x0d / 0x0c),
0x3a (1…10, перед каждой группой записей; похоже на метку шага), 0x13 (только E, 1000). nouveau их тоже пропускает
(в его коде они остались комментариями).
